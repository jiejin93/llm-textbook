前言

为什么写这本书

2020 年前后，如果你问一位深度学习工程师“语言模型能做什么”，得到的答案多半是“补全句子、做翻译、写摘要”。而今天，大语言模型（Large Language Model, LLM）已经能够编写可运行的程序、推导数学证明的步骤、阅读图表回答问题，甚至作为智能体（Agent）自主调用工具完成复杂任务。这一变化的核心，是一条看似简单到令人怀疑的路径：在海量文本上，训练一个预测下一个词的神经网络。

正是这条路径的“简单”与效果的“惊人”之间的巨大反差，使得许多掌握了深度学习基础的开发者产生了同样的困惑：

  • 我懂 CNN、RNN、反向传播，也写过 PyTorch，但为什么就是看不懂 Transformer 论文里的 Q、K、V 到底在做什么？
  • 网上的教程要么停留在“十行代码实现 GPT”，要么直接跳到“用 vLLM 起一个服务”，中间的预训练数据工程、分布式训练、RLHF 后训练去哪里学？
  • 想动手训练一个自己的模型，从哪里获得数据、需要多少显存、怎么评估效果、又怎么量化压缩后部署上线？

市面上的资料大致分两类：一类是学术论文与前沿技术报告，默认读者已经掌握全部背景；另一类是框架使用教程，教你调用 API 却不解释背后的原理。缺的是一本介于两者之间、把“从 Transformer 结构”到“生产环境部署”完整贯通的系统性教材。 这本书就是为了填补这个空缺。

这本书讲什么

本书的书名已经概括了主线：从 Transformer 到部署。全书由第 0 章数学准备（选读）、17 章正文与 3 个附录组成，正文分为六个部分，沿着“一个 LLM 是如何被造出来并投入使用”的完整生命周期展开：

  1. 基础（第 1–4 章）：LLM 全景与语言建模的概率视角、Transformer 的逐模块剖析与最小可运行实现、分词器（BPE 等）。
  2. 预训练（第 5–9 章）：数据清洗与去重、优化器与训练稳定性、Scaling Laws、数据/张量/流水线等分布式训练、混合专家模型（MoE）。
  3. 微调与评测（第 10–11 章）：SFT 与 LoRA/QLoRA、主流评测基准与评测方法论。
  4. 后训练（第 12–13 章）：策略梯度与 PPO 的完整推导、RLHF 三阶段、DPO、GRPO 与推理模型（R1 式）训练。
  5. 推理与部署（第 14–15 章）：KV Cache、FlashAttention、PagedAttention 与 vLLM、各类量化方法（GPTQ/AWQ/FP8）、服务化与监控。
  6. 多模态与前沿（第 16–17 章）：ViT、CLIP、LLaVA 式视觉语言模型的设计与训练、推理模型与 Agent 等前沿专题。

在正文六个部分之前是第零部分 数学准备（选读）：第 0 章 面向大模型的数学基础，内容是线性代数、概率与信息论、微积分与矩阵求导、优化和浮点数表示。它不计入正文的 17 章编号，读法只有一句话：不确定就读，确定了就跳过，卡住了再回来查（具体建议见“如何使用本教材”）。

正文之后还有三个附录，供随时查阅：附录 A 数学符号表（全书符号速查，看公式卡住时先查它）、附录 B 常用开源仓库与资料清单（按章节整理的仓库、课程与文档链接）、附录 C 术语中英对照表（统一中文译名，中英对照）。六部分正文加第 0 章与三个附录，才构成这本书的完整目录，如图 P-1 所示。

本书不满足于“讲清楚是什么”，而是力求让你在合上书后能够独立完成：读懂一份现代 LLM 的架构代码并指出它与 GPT-2 的差异；规划一次预训练或微调的显存与算力；选择并实现合适的评测；用 RLHF/DPO/GRPO 做对齐；用量化和推理引擎把模型部署成高吞吐服务。

读者画像与先修要求

本书假设你已经具备一门“深度学习入门课”的水平，具体来说：

  • 理解神经网络的前向传播与反向传播（Backpropagation），能手推简单网络的梯度；
  • 用过 PyTorch，会写训练循环（forward → loss → backward → step）、会搭 nn.Module；
  • 了解 CNN 与 RNN/LSTM 的基本思想——本书会在第 2 章 2.3 节快速回顾从 n-gram 到神经语言模型的发展，但不会从“什么是神经网络”讲起；
  • 具备基础的线性代数、概率论与微积分：矩阵乘法与转置、softmax\mathrm{softmax}softmax、条件概率与期望、链式法则。这一条不是客套话：第 3 章用矩阵形式推导注意力（含 softmax 的雅可比），第 7 章要读懂 C≈6NDC \approx 6NDC≈6ND 与幂律拟合，第 8 章要按 16N16N16N 估算显存。如果你对这几项已经生疏，请先花 3–5 小时读第 0 章。

你不需要已经了解 Transformer、注意力机制或任何 LLM 训练细节——这些正是本书要教给你的。 你也不需要“数学很好”：所有公式都从本科低年级的基础推起，第 0 章就是为补齐这些基础而写的“数学补丁”，附录 A 另提供全书符号速查表。

如果你符合上述画像，本书的难度曲线是为你设计的：第 3 章（Transformer 详解）与第 8 章（分布式训练）是全书最陡的两段爬坡，我们会用大量图示、逐行代码和数值例子帮你过关。经验上，只要第 3、4 章的代码亲手跑通，后面的章节会顺很多；如果反复卡在符号上，回看第 0.2 节（线性代数）与第 0.5 节（微积分与矩阵求导）通常就能解开。

如何使用本教材

先选一条路线。 不同的目标不需要读同样的章节。下面三条路线的章节范围与时间投入是经验估计（按每周投入 6–10 小时计；“读完”指读完正文并至少完成各章的编程题）：

  • 完整路线（读到第 17 章，约 120–180 小时／一个学期）：按第 1–17 章顺序通读，第 0 章按需查阅，每章完成配套代码与练习。第 1–4 章打地基，第 5–9 章进入预训练深水区，第 10–15 章是工程实战最密集的部分，第 16–17 章扩展视野。适合想系统建立完整认知、要做技术选型或准备深入研究的读者。
  • 应用工程师路线（读到第 15 章，约 40–60 小时／6–8 周业余时间）：第 1–4 章 → 第 10 章 → 第 14–15 章，目标是“会用、会微调、会部署”。第 5–9 章与第 12–13 章可以只读各章导语与本章小结，遇到 ZeRO、MoE、DPO 这类名词时回查对应小节，不必精读推导。适合马上要在业务里落地模型的读者。
  • 研究者路线（读到第 17 章，约 200 小时以上）：第 0 章通读，第 1–17 章通读并精读第 3、7、8、13 章，同时完成第 6 章的 TinyStories 预训练实战与第 13 章的 GRPO 实验。适合要读论文、复现方法或准备做 LLM 方向研究的读者。

第 0 章什么时候读。 三条路线都不要求“先学完数学再开始”，第 0 章是补丁而不是门槛：

  • 可以跳过：如果你能顺畅看懂矩阵乘法 ABABAB 的形状、softmax\mathrm{softmax}softmax 的输入输出、条件概率与期望、链式法则，以及“为什么 FP16 会溢出”，那就直接进第 1 章。
  • 建议先读：如果上面任何一项让你犹豫，先花 3–5 小时读第 0 章（重点 0.2 线性代数、0.4 信息论、0.5 微积分与矩阵求导），再回来读第 1 章。这几小时会在第 3 章加倍赚回来。
  • 卡壳了再回来读：第 2 章看不懂交叉熵与困惑度 → 回看第 0.4 节；第 3 章注意力推导卡在矩阵形状或 softmax 的雅可比 → 回看第 0.2 节与第 0.5 节；第 6 章混合精度里不明白 FP16 为什么上溢 → 回看第 0.7 节。附录 A 的符号表可以当作常备索引，不必强记。

配套代码。 本教材的口号是“每个关键概念都有可运行的代码”。书中每一段代码都写成可直接运行的形式：给出了所需的安装命令、关键参数与预期输出，可以按章复制到本地 GPU、实验室服务器或 Colab 上跑通。配套的完整代码（训练脚本、数据下载与依赖清单）随本教材一并发布，获取方式见书末说明。代码风格遵循三个原则：优先正确与可读，其次才是性能；每个超参数显式写出，不藏在配置文件深处；与工业界主流实现（如 nanoGPT、HuggingFace Transformers）对照给出链接，帮你从“教材代码”过渡到“生产代码”。

练习。 每章末尾的练习统一按三组编排：概念题（检验理解）、编程题（动手实现）、思考题（没有标准答案，训练科研品味）；动手量较大的章节会在最后追加一个实操项目（一个完整的动手任务，给出输入、输出与验收标准）。强烈建议至少完成编程题——LLM 是一门实践学科，看懂与写出来之间隔着一条鸿沟。

阅读方法。 第一遍读可以跳过所有推导，只看图、代码与小结；第二遍精读公式推导（尤其是第 3 章注意力机制、第 12–13 章强化学习部分），建议拿纸笔跟随；第三遍把书当手册查阅。数学符号全书统一，附录 A 提供符号表，附录 C 提供术语中英对照表。

硬件与成本。 本书的实战代码按“尽量让读者跑得起来”设计。各章的最低配置是（汇总于第 1 章表 1-3）：第 3 章最小 GPT 训练约 4 GB 显存（CPU 也能跑，只是慢得多）；第 6 章 TinyStories 预训练约 8 GB；第 10 章 LoRA 微调 7B 约 16 GB、QLoRA 约 8 GB（同为 7B 模型，全参微调要 100 GB 量级，见第 10 章 10.5 节）；第 13 章在小模型上跑 GRPO 约 24 GB；第 14–15 章用 vLLM 部署 7B 约 20 GB。换算成硬件，可以这样理解：

  • 一张 24 GB 的消费级显卡（RTX 3090/4090）足够走完绝大部分主线：从零训练 10M–100M 参数的小 GPT、用 QLoRA 微调 7B 甚至 13B（4 bit 量化后权重只有数 GB）、以 BF16 部署 7B 模型做推理（权重约 14 GB，剩下的显存要留给 KV Cache——上下文越长，能并发的请求越少，详见第 14 章 14.2 节）。但全参微调 7B，或从零预训练 1B 以上的模型，24 GB 就不够了。
  • 免费算力够不够用：Google Colab 免费额度提供 T4（16 GB 显存），跑通第 3 章的最小 GPT、缩小规模的第 6 章 TinyStories 实验、以及 7B 模型的 4 bit 推理都没问题；但免费会话有闲置断开与时长上限，长训练必须配合 checkpoint 与网盘挂载（第 6 章 6.7 节），否则容易白跑。国内平台（如 AutoDL）按小时租卡，可以连续开机、按量计费，更适合需要跑数小时训练的场景。
  • 必须多卡、只能“读＋算”的章节：第 8 章（分布式训练）的 DDP、ZeRO、张量并行、流水线并行，只有真正跑在多卡上才有体感；单卡读者建议按第 8 章 8.1 节的显存公式把每种策略“算一遍”（书中有 16N16N16N 法则与可直接复算的例子），并把并行代码当作对照阅读。第 9 章（MoE）的完整训练同样需要多卡（专家并行依赖 all-to-all 通信），单卡上能做的是第 9 章 9.7 节“60 行内的简化 MoE 层”那一类实验（观察路由与负载均衡的真实行为），外加显存与算力的账目估算。这两章的目标是“看懂并能规划”，而不是“人人都在本机复现”。
  • 公有云 GPU 的价格量级：要用云上算力，请先算成本再开机。按公开报价的量级看，海外平台单张数据中心级显卡（B200/H100 级）约每小时 5–8 美元（Stanford CS336 课程页面为自学者列出的公开报价，会随行情更新）；国内平台按小时计费，从消费级卡到数据中心卡大致横跨“每小时几元”到“每小时几十元”人民币两个量级。价格随平台、地区、库存与计费方式（按量、竞价、包月）波动很大，请以平台实时报价为准；做实验时优先保证“随时能停、随时能续”。
