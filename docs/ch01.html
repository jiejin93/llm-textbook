2022 年 11 月底，ChatGPT 上线，五天收获一百万用户，两个月月活过亿——这个速度超过了此前所有消费级互联网产品。人们突然意识到：一个只被训练来“预测下一个词”的神经网络，竟能写代码、做翻译、解数学题、进行多轮对话。这场变革并非一夜发生，而是近四十年语言建模技术持续演进、并在“规模”（scale）的杠杆下发生质变的结果。

1.1 什么是大语言模型

1.1.1 语言建模：从概率到生成

语言模型（Language Model, LM）的本质，是对自然语言的概率分布建模：给定一段文本，计算这段文本出现的概率。用形式化语言描述，设一个长度为 TTT 的词序列 w=(w1,w2,…,wT)w = (w_1, w_2, \dots, w_T)w=(w1​,w2​,…,wT​)，语言模型给出其联合概率 P(w1,…,wT)P(w_1, \dots, w_T)P(w1​,…,wT​)。直接建模联合概率很困难，概率链式法则（chain rule of probability）告诉我们，可以把它分解为一系列条件概率的连乘：

P(w1,w2,…,wT)=∏t=1TP(wt∣w1,…,wt−1)P(w_1, w_2, \dots, w_T) = \prod_{t=1}^{T} P(w_t \mid w_1, \dots, w_{t-1})P(w1​,w2​,…,wT​)=t=1∏T​P(wt​∣w1​,…,wt−1​)

也就是说，“建模一段话的概率”等价于“反复预测下一个词”。这就是自回归（autoregressive）语言建模：每次以已生成的全部前文为条件，预测下一个 token 的概率分布 P(wt∣w<t)P(w_t \mid w_{<t})P(wt​∣w<t​)（为书写简洁，本书用 w<tw_{<t}w<t​ 表示 w1,…,wt−1w_1, \dots, w_{t-1}w1​,…,wt−1​，这一记号在第 2 章、第 3 章继续沿用）。大语言模型就是用极深的神经网络（在本书中几乎总是 Transformer）来实现这个条件分布的模型，“大”指的是参数量大——现代 LLM 从数十亿（B，billion）到上万亿参数不等。

⚠️ 符号提示：本章（与附录 A 一致）用 TTT 表示序列长度，第 2 章沿用；第 0 章与第 3 章改用 nnn、第 8 章改用 SSS，四者同义。另外注意 TTT 在第 7–8 章另指训练时间、第 9 章指每层 token 数，看到时按上下文区分即可。完整的记号约定见第 2 章 2.1 节。

“预测下一个词”这个目标看似简单，实则是通用的：要把下一个词预测得准，模型隐式地必须掌握语法、事实知识、常识推理，甚至代码逻辑。例如，要预测“法国的首都是__”的下一个词，模型必须“知道”巴黎；要预测一段 Python 代码的下一个 token，模型必须“理解”缩进规则与变量作用域。下一 token 预测因此被称为一种自监督学习（self-supervised learning）：监督信号（下一个词是什么）直接来自数据本身，无需人工标注，这使得训练数据可以扩展到互联网规模的万亿 token。

📌 注：本节用“词”（word）称呼序列单元 wtw_twt​，是为了让链式法则的记号与第 0 章概率部分保持一致。在实际系统中，模型处理的最小单位是 token——由分词器（第 4 章）切出的子词片段，可能是整词（“学习”）、词的一部分（“ization”）或单个字节。本书第 2 章之后会逐渐统一使用 token 记号，两者的数学角色完全相同：都是离散词表 VVV 中的一个元素。更多背景可参考维基百科的大语言模型条目（其中 Tokenization 一节即第 4 章的主题）。

⚠️ 符号提示：这里的 VVV 是词表大小（第 2、4 章同义）；第 3 章注意力公式里的 VVV 是值矩阵（Value），两者只是碰巧同名。词表越大、参数越多这件事，第 4 章会算成具体数字。链式法则从概率论角度的来龙去脉见第 0 章 0.3.4 节，正式定义与数值例子见第 2 章 2.1 节。

生成（generation）则是在训练好的模型上反复执行：采样一个 token，拼回输入，再预测下一个，循环往复。这个“一次预测一个、喂回去再预测”的过程称为自回归解码（autoregressive decoding），是第 14 章推理优化的核心对象。

1.1.2 能力涌现：规模的魔法

一个令人惊讶的经验现象是：许多能力并非随规模线性增长，而是在参数量跨过某个阈值后才突然出现，这就是涌现能力（emergent abilities）。Wei et al.（2022）系统报告了这一现象：在数十亿参数以下，模型做多位数加法的正确率接近随机；跨过阈值后，正确率陡然跃升。类似地，思维链（Chain-of-Thought, CoT） prompting 带来的推理增益，也主要出现在百亿参数以上的模型中。

对涌现现象的解释存在争议。一种观点（Schaeffer et al., 2023）认为，部分“涌现”是评测指标非线性（如“完全答对才得分”的离散指标）造成的假象，换成连续指标后能力增长其实是平滑的。

📌 注：如果你对“规模变大为什么会产生质变”缺少直觉，可以把下一 token 预测想象成无数个难度不一的子任务（拼词、搭配、事实、推理）的混合：小模型把算力花在最常见的子任务上，长尾任务的表现停留在随机水平，因此在“完全答对才得分”的指标上得分接近零；规模扩大后长尾任务陆续越过随机基线，宏观上就表现为“突然会了”。想看更直观的可视化讲解，推荐 3Blue1Brown 的深度学习系列：第 5 章《But what is a GPT?》建立整体直觉，第 6 章《Attention in transformers》逐步拆解注意力。

本书第 7 章将回到这一争论。无论解释如何，工程事实是清楚的：规模本身是能力的重要来源，参数量、数据量、算力三者需要协同扩展——这正是 Scaling Laws（规模定律）研究的对象，也是现代 LLM 区别于传统 NLP 模型的根本特征。

1.2.1 统计时代：n-gram 与香农的游戏

1948 年，香农（Claude Shannon）在《通信的数学理论》中建立了信息的度量，并以字母级的 n-gram（零阶、一阶、二阶 digram、三阶 trigram 近似）来逼近英语的统计结构，据此估计英语的冗余度约为 50%——也就是说，只利用不超过八个字母范围内的统计结构，书面英语中约有一半内容是“可预测”的。1951 年他又在《Prediction and Entropy of Printed English》中设计了著名的“人类预测下一个字母”实验：让受试者逐字母猜测文本，用猜中率把英语的熵下推到每字符约 1 bit 的量级。此后数十年，基于计数和平滑（smoothing）的 n-gram 模型一直是语音识别与机器翻译的标准组件。它的根本缺陷在第 2 章会详细讨论：稀疏性——绝大多数合法的词组合在训练数据中从未出现，参数量随阶数指数增长，长程依赖无从谈起。

1.2.2 神经时代：从 NNLM 到 RNN/LSTM

2003 年，Bengio 等人的神经概率语言模型（Neural Probabilistic Language Model, NNLM）迈出关键一步：用神经网络的词嵌入（word embedding）表示词，再把前 n−1n-1n−1 个词的嵌入拼接后经多层网络预测下一个词。这一工作引入了两个影响深远的思想——分布式词表示与参数共享，使模型能对未见过的词组合给出合理的概率泛化。2013 年 word2vec 把“分布式表示”推向极致，2014 年 Seq2Seq 与注意力机制（attention，最初作为 RNN 翻译系统的对齐组件）登场。RNN/LSTM 虽能处理任意长度序列，但其顺序计算无法并行、且长距离信息经反复传递容易衰减，制约了规模扩展——这两个痛点正是 Transformer 的直接靶子。

1.2.3 规模时代：Transformer 与 GPT 系列

2017 年，Google 的《Attention Is All You Need》提出 Transformer：抛弃循环结构，完全依靠自注意力（self-attention）在任意两个位置之间直接传递信息，训练可完全并行。Transformer 是现代所有 LLM 的骨架，第 3 章将逐模块剖析。

2018–2020 年，GPT 系列验证了“Transformer 解码器 + 大规模下一词预测”路线的威力：

  • GPT-1（2018，1.17 亿参数）：首次展示“无监督预训练 + 有监督微调”的两段式范式，在多个 NLP 任务上达到当时最优。
  • GPT-2（2019，15 亿参数）：发现规模扩大后，模型无需微调即可通过零样本提示（zero-shot prompting）完成多任务，于是“通用语言模型”的构想开始成形。
  • GPT-3（2020，1750 亿参数，约 3000 亿 token 训练）：参数量扩大百倍以上后，上下文学习（in-context learning）出现——在提示里给几个示例，模型就能照做新任务，无需更新任何权重。GPT-3 的论文标题直接点题：“Language Models are Few-Shot Learners”。

1.2.4 对齐时代：InstructGPT 与 ChatGPT

GPT-3 虽强，却像一个“文献续写器”而非“助手”：用户问它问题，它可能接着写“还有人问……”而不是回答。2022 年初的 InstructGPT（Ouyang et al., 2022）给出解法，确立了RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）三阶段流程：先监督微调（SFT）教会模型遵循指令，再训练奖励模型（RM）为回答打分，最后用强化学习（PPO）优化模型去最大化奖励。ChatGPT 正是这套配方的产品化，RLHF 让“续写器”变成了“对话助手”。此后 DPO、GRPO 等更简洁的对齐方法相继出现，2025 年初 DeepSeek-R1 展示了用 GRPO + 可验证奖励（RLVR）就能激发出长链推理能力，把后训练推向了新阶段。这些将在第 12–13 章完整展开。

1.2.5 开源浪潮：Llama、Qwen 与 DeepSeek

GPT-3 之后，开源社区从追赶到并跑。Meta 的 Llama（2023.2，7B–65B）与 Llama 2（2023.7，7B/13B/70B）确立了“开源权重 + 现代架构（RMSNorm、RoPE、SwiGLU、GQA）”的事实标准，Llama 3（2024.4，8B/70B，后续 405B）进一步缩小了与闭源模型的差距。同期 Mistral 7B（2023.9）以小胜大，Mixtral（2023.12）把混合专家（MoE）架构带入开源视野。国内的 Qwen（阿里通义千问）系列持续迭代，Qwen2.5 覆盖 0.5B–72B 并成为开源社区微调最频繁的基座之一；DeepSeek-V3（2024.12，671B 总参数、约 37B 激活的 MoE）以极低的训练成本引发关注，DeepSeek-R1（2025.1）则以开放权重复现了 o1 级别的推理能力。今天，一个开发者用一张消费级显卡就能运行 7B 级模型、用 LoRA 微调出自己的助手——这在 2020 年是不可想象的。

1.3 预训练—微调—对齐：LLM 的三级流水线

现代 LLM 的生产流程可以概括为三段式流水线（图 1-2），各段目标、数据与算力消耗截然不同。图中的百分数指训练算力的占比，“反馈回流”虚线则对应第 14–15 章的部署与迭代环节：

图 1-2　LLM 生产的三级流水线：预训练—微调（SFT）—对齐

  • 预训练（pre-training）：在数万亿 token 上做下一词预测，学会语言、知识与初步推理。消耗了绝大部分算力（GPT-3 级模型训练一次需要数千张 GPU 跑数周），产出的是“基座模型”（base model）。
  • 监督微调（Supervised Fine-Tuning, SFT）：用人工编写的高质量“指令→回答”对继续训练，把基座从“续写机器”变成“听指令办事的模型”。数据量骤降至万级到百万级，算力需求小几个数量级。
  • 对齐（alignment）：通过人类偏好数据 + 强化学习，进一步塑造模型的行为边界——更有帮助、更诚实、更无害（Helpful, Honest, Harmless，即 3H）。SFT 教模型“做什么”，对齐在诸多可行回答中挑选“人类更偏好的那种”。

一个常见的误解是把三段流水线当作严格串行的“官方流程”。实践中它是灵活的：小模型可以直接蒸馏；RLHF 之后常再补一轮 SFT；DeepSeek-R1 甚至展示了“纯 RL（可验证奖励）+ 少量冷启动数据”也能造就强推理模型。但作为思维框架，“预训练给能力、微调给形式、对齐给价值观”是理解一切后训练技术的钥匙。

  • 数据量：经验上，训练 token 数与参数量的比值（“重复度”）在 Chinchilla 最优附近约为 20:1（第 7 章），但现代模型普遍远超此比例（Llama 3 为 15T/8B ≈ 1875:1），靠数据重复利用换取小参数高性能。
  • 算力：训练总计算量常用 C≈6NDC \approx 6NDC≈6ND 估算（NNN 为参数量，DDD 为 token 数；推导见第 3 章 3.12.2 节）。一张 H100 SXM 的 BF16 稠密算力峰值为 989 TFLOPS（厂商标称，PCIe 版为 756 TFLOPS），但实际训练的算力利用率（MFU）通常只有 30%–50%，所以估时间时必须用“有效算力 = 峰值 × 利用率”。按此口径，训练一个 8B 模型 15T token 约需 6×8×109×15×1012=7.2×10236 \times 8\times10^{9} \times 15\times10^{12} = 7.2\times10^{23}6×8×109×15×1012=7.2×1023 FLOPs，1024 张 H100 按 45% 利用率也要跑约 18 天——即便千卡集群也绝非“跑一晚上”的事。这套估算与峰值口径在第 7、8、15 章会反复用到。
  • ⚠️ 符号提示：本小节的 NNN 指模型参数量、DDD 指训练 token 总数。同名不同义的情况在第 9 章出现（那里 NNN 是专家数）、第 2 章也有（那里 NNN 用来数语料中的样本总数，DDD 表示训练语料集合）；CCC 则在第 11 章被借去表示上下文。

1.4.1 算力之外的隐藏成本

初学者容易把 LLM 的门槛等同于“买得起多少张显卡”，实际上预训练还有三块常被低估的成本。数据工程：从 Common Crawl 到可训练语料需要经过抓取、抽取、清洗、去重、配比等长管线（第 5 章），其工程量与调参难度不亚于训练本身；业界常说“垃圾进、垃圾出”，数据质量的细微差异会在最终模型能力上被放大。实验与迭代：一次大规模预训练动辄数周，期间任何一次 loss spike 都可能浪费数十万元算力，因此必须先用小模型、短训练做充分的消融实验（这依赖第 7 章 Scaling Laws 提供的外推能力），再放大到目标规模。评测：训练完成只是开始，要回答“这个模型到底好不好、好在哪里、差在哪里”，需要系统化的评测体系（第 11 章）。理解这三块隐藏成本，有助于你在阅读本书后续章节时明白：为什么我们要花整整五章讲预训练，而不是只讲一个训练循环。

1.4.2 一个常见的规模误区

“参数越多越好”是新手最常见的误区。事实上，在固定算力预算下，参数量与数据量存在最优配比（Chinchilla 定律，第 7 章）：盲目堆参数而数据不足，模型会“欠训练”，性能反而不如更小但喂饱数据的模型。而在部署侧，推理成本几乎随参数量线性增长，第 14 章会展示同一模型的不同量化版本在精度与速度之间的权衡。规模是一个三维（参数、数据、算力）联合优化问题，而不是一个单维军备竞赛——DeepSeek-V3 用 671B 总参数、约 37B 激活的稀疏设计在成本与能力之间取得平衡，正是这一思想的好例子。

1.5 本教材路线图

全书正文共 17 章（另有第 0 章“面向大模型的数学基础”作为选读准备、3 个附录），按“基础 → 预训练 → 微调评测 → 后训练 → 部署 → 多模态与前沿”六部分推进（前言中的路线图给出了完整依赖关系）。就本章之后的路径而言：第 2 章补齐语言建模的概率基础与解码策略，第 3 章深入 Transformer 并亲手实现最小 GPT，第 4 章解决文本如何变成 token 的问题——这四章是全书的地基。此后无论你走向预训练工程（第 5–9 章）、微调与评测（第 10–11 章）、对齐研究（第 12–13 章）还是推理部署（第 14–15 章），都建立在这块地基之上。

本章小结

  • 语言建模 = 用链式法则把序列概率分解为条件概率连乘，LLM 用超大神经网络实现 P(wt∣w<t)P(w_t \mid w_{<t})P(wt​∣w<t​)，即下一 token 预测；该目标自监督、可扩展，是能力涌现的土壤。
  • 发展史的主旋律是“可扩展性”：n-gram 受稀疏性所限 → NNLM 引入分布式表示 → RNN 受顺序计算所限 → Transformer 实现全并行 → GPT-3 验证规模 → InstructGPT/ChatGPT 解决对齐 → Llama/Qwen/DeepSeek 开源浪潮。
  • 现代 LLM 生产是三级流水线：预训练（能力，消耗绝大部分算力）→ SFT（指令形式）→ 对齐（偏好与安全）。
  • 参数（B 级到千亿级）、数据（万亿 token 级）、算力（C≈6NDC \approx 6NDC≈6ND，e23–e25 FLOPs）三个数字是讨论一切 LLM 的坐标系。
  • 环境准备：Python + PyTorch 2.x + HuggingFace 全家桶，无 GPU 可用 Colab / 国内云平台，下载用 hf-mirror 镜像。
  • 通向下一章：下一章我们把本章反复用到的两个词——“概率”与“下一 token”——真正算清楚：语言模型到底在优化什么目标、怎样衡量好坏（交叉熵与困惑度）、以及怎样从它输出的分布里采样出文本；这些正是第 3 章 Transformer 要拟合的那个函数。

编程题

练习 A：用 pipeline 跑一个小模型问答。 HuggingFace 的 pipeline 是调用 LLM 的最短路径，先用它建立“模型—分词器—生成”的整体印象（各组件分别在第 3、4 章拆解）。示例依赖 transformers 与 torch（pip install transformers torch），并会从 HuggingFace 下载约 1 GB 的权重，CPU 上几分钟内可跑完。

from transformers import pipeline

gen = pipeline("text-generation", model="Qwen/Qwen2.5-0.5B")  # 基座模型，CPU 也能跑

prompt = "问题：法国的首都是哪里？\n答案："
out = gen(prompt, max_new_tokens=20, do_sample=False)  # do_sample=False 即贪心解码
print(out[0]["generated_text"])
# 输出（截断示意）：'问题：法国的首都是哪里？\n答案：巴黎。'
# 模型只见过"续写"，却回答了问题——第 1.1.1 节"下一词预测蕴含知识"的直接证据

# 换一个对话格式的 pipeline，体验指令模型与基座模型的区别
chat = pipeline("text-generation", model="Qwen/Qwen2.5-0.5B-Instruct")
msgs = [{"role": "user", "content": "用一句话解释什么是注意力机制。"}]
print(chat(msgs, max_new_tokens=60)[0]["generated_text"][-1]["content"])

练习 B：亲手验证“续写器 vs 助手”。 用同一个问题分别问基座模型与指令模型，观察 1.2.4 节描述的行为差异。下例的预期现象是：基座模型接着“编造更多问题”，而指令模型会真正回答。

from transformers import pipeline

base = pipeline("text-generation", model="Qwen/Qwen2.5-0.5B")
q = "北京有什么好玩的景点？"
print(base(q, max_new_tokens=50, do_sample=False)[0]["generated_text"])
# 输出（截断示意，基座模型做的是"续写"）：
#   '北京有什么好玩的景点？\n上海有什么好玩的景点？\n广州有什么好玩的景点？...'
inst = pipeline("text-generation", model="Qwen/Qwen2.5-0.5B-Instruct")
print(inst([{"role": "user", "content": q}], max_new_tokens=100)[0]
      ["generated_text"][-1]["content"])
# 输出：指令模型会真正列举景点（故宫、长城、颐和园……）——SFT+对齐带来的行为改变

练习 C：规模直觉计算器。 把 1.4 节的估算公式写成函数，批量比较几个模型（注意 util 就是 1.4 节说的 MFU，默认取 45%；tflops_per_gpu 默认取 H100 SXM 的 BF16 稠密峰值 989 TFLOPS）。

def train_flops(n_params_b, tokens_t):
    """C ≈ 6ND。参数单位十亿(B)，token 单位万亿(T)。"""
    return 6 * n_params_b * 1e9 * tokens_t * 1e12

def gpu_days(flops, gpus=1024, tflops_per_gpu=989, util=0.45):
    """有效算力 = 峰值 × 利用率；返回 gpu·天 数。"""
    eff = gpus * tflops_per_gpu * 1e12 * util
    return flops / eff / 86400

for name, n, d in [("Llama-2-7B", 7, 2), ("Llama-3-8B", 8, 15), ("Qwen2.5-72B", 72, 18)]:
    c = train_flops(n, d)
    print(f"{name}: C≈{c:.2e} FLOPs, 1024卡约 {gpu_days(c):.0f} 天")

预期输出（C 单位为 FLOPs，卡数指 1024 张 H100 SXM、按 45% 利用率计）：

Llama-2-7B: C≈8.40e+22 FLOPs, 1024卡约 2 天
Llama-3-8B: C≈7.20e+23 FLOPs, 1024卡约 18 天
Qwen2.5-72B: C≈7.78e+24 FLOPs, 1024卡约 198 天

其中 Llama-3-8B 一行的“18 天”与 1.4 节正文的估算完全一致（同一模型、同一批卡），可以用来互相验证。

这段代码的公式可以用官方报告来对账：Llama 3 技术报告披露 405B 旗舰模型的预训练算力为 3.8×10253.8\times10^{25}3.8×1025 FLOPs（在 15.6T token 上训练），而用练习 C 的 train_flops(405, 15.6) 算出来是 6×405×109×15.6×1012≈3.79×10256 \times 405\times10^{9} \times 15.6\times10^{12} \approx 3.79\times10^{25}6×405×109×15.6×1012≈3.79×1025 FLOPs——两者吻合。把 gpus 与 tflops_per_gpu 换成你自己的硬件参数，就能估算手头的任务要跑多久。
