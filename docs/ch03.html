第 3 章 Transformer 详解

Transformer 是现代大语言模型（LLM）的基石。从 GPT、Llama 到 DeepSeek、Qwen，几乎所有主流大模型都建立在同一个骨架上：自注意力（self-attention）+ 前馈网络（FFN）+ 残差连接 + 归一化层，堆叠几十层而成。本章将从 RNN 的痛点出发，完整推导注意力机制，逐一拆解每个组件的原理与演进，横向对比从原始 Transformer 到 Llama 的架构变迁，最后从零实现一个约 150 行、可直接运行的迷你 GPT。学完本章，你应当能够：读懂任何一个现代 LLM 的模型代码，并估算它的参数量与训练计算量。

3.1 从 RNN 到注意力

3.1.1 RNN 的两大痛点

在第 2 章我们回顾了 RNN / LSTM 语言模型。它按时间步逐词处理序列：

ht=tanh⁡(Whhht−1+Wxhxt+b)h_t = \tanh(W_{hh} h_{t-1} + W_{xh} x_t + b)ht​=tanh(Whh​ht−1​+Wxh​xt​+b)

这带来两个根本性问题：

  1. 无法并行。hth_tht​ 依赖 ht−1h_{t-1}ht−1​，训练时必须顺序计算 nnn 个时间步。GPU 擅长大规模并行矩阵乘法，RNN 却把计算拆成一连串小步，硬件利用率极低。序列越长，训练越慢，而大模型恰恰需要在万亿 token 的长文本上训练。

  2. 长程依赖衰减。要让第 1000 步的隐状态”记住”第 1 步的信息，信息必须经过 999 次矩阵乘法与非线性压缩。即便有 LSTM 的门控机制，梯度在时间上反向传播时仍会发生指数级衰减或爆炸（通过连乘 ∏tWhh\prod_t W_{hh}∏t​Whh​），远距离的依赖很难学到。

此外，RNN 的隐状态是一个固定维度的向量，相当于用一个”瓶颈”压缩整段历史，信息容量有限。

三个问题可以用一个统一视角理解：RNN 把”序列上的信息路由”与”时间上的计算调度”耦合在了一起——信息只能沿时间轴逐步流动，计算也只能沿时间轴逐步执行。要打破这两个耦合，就需要一种让任意两个位置直接交换信息的机制，同时把整个序列的计算组织成可以一次完成的大矩阵运算。这正是注意力做的事。

3.1.2 注意力的核心思想

注意力机制给出了一种完全不同的信息交换方式：不要逐步传递信息，让序列中每个位置直接”看到”所有位置，按相关性加权取用信息。

直觉上，处理句子”小猫追着球跑，它玩得很开心”中的”它”时，我们希望模型能直接把”它”与”小猫”关联起来，而不是指望一个隐状态把”小猫”的信息扛过若干时间步。注意力把这种”直接关联”变成了可微分的矩阵运算：

  • 每个位置的信息汇聚不再依赖序列距离，任意两个位置的路径长度都是 O(1)O(1)O(1)；
  • 整个序列的计算是一次大矩阵乘法，完美匹配 GPU。

2017 年，Vaswani 等人在论文 Attention Is All You Need（arXiv:1706.03762）中提出：干脆完全抛弃循环结构，只用注意力 + 前馈网络，即 Transformer。此后它统治了 NLP，进而统治了几乎所有模态。

3.2 注意力机制完整推导

3.2.1 Query / Key / Value 的直觉

注意力可以类比”软性字典查询”（soft dictionary lookup）：

  • Query（查询，Q）：当前位置”我想找什么信息”；
  • Key（键，K）：每个位置”我能提供什么信息”的索引；
  • Value（值，V）：每个位置实际携带的内容。

普通字典是硬查询：用 key 精确匹配，返回唯一 value。注意力是软查询：用 Query 与所有 Key 计算相似度，相似度越高，对应的 Value 被取用的权重越大，最终返回所有 Value 的加权平均。

📌 注：”软性字典查询”是理解 Q/K/V 的最常用类比，但别把它看得太死：字典的 key 匹配是精确等值，而注意力是基于向量相似度的加权检索，因此”查”的结果永远是全体条目的混合，只是权重悬殊时看起来像精确命中。想看更细的图解，推荐 Jay Alammar 的 The Illustrated Transformer 与 3Blue1Brown 的 Transformer 注意力可视化视频；数学定义见维基百科 Attention (machine learning))。

具体地，对输入序列 X∈Rn×dmodelX \in \mathbb{R}^{n \times d_{\text{model}}}X∈Rn×dmodel​（nnn 个 token，每个是 dmodeld_{\text{model}}dmodel​ 维向量），用三个可学习矩阵做线性投影：

3.3.2 为什么要多头

  • 表达多样性：不同头可以在不同子空间学到不同模式。可视化研究表明，训练后的模型中确实存在”关注前一个词”“关注句法主干”“关注标点/分隔符”等分工明确的头。
  • 相当于集成：hhh 个小注意力并联再线性融合，比单个大注意力更稳定。
  • 代价几乎为零：h×dk=dmodelh \times d_k = d_{\text{model}}h×dk​=dmodel​，多头并不增加投影矩阵的总参数量与计算量，只是把同样大的矩阵切成 hhh 份、各自产生 n×nn \times nn×n 的得分矩阵。

3.3.4 注意力头到底学到了什么

训练好的 Transformer 中，把注意力权重矩阵画成热图（行 = query 位置，列 = key 位置），能观察到清晰的分工：有的头几乎只看前一个位置（学到类似 bigram 的局部依赖），有的头聚焦句首的”主题词”，有的头在标点或分隔符之间跳跃（分段），还有的头呈现”对角线略偏移”的模式（局部窗口，近似卷积）。据此有人提出”用注意力权重做可解释性分析”的思路，但需谨慎：注意力权重高不等于因果上重要。对本书更有价值的是一个工程结论：大量头是冗余的——这为推理时的头剪枝、以及 GQA 把 KV 头数从 hhh 压到几组提供了经验依据。

3.4 因果掩码与自回归解码

语言模型是自回归的：第 ttt 个词的概率只依赖前 t−1t-1t−1 个词，P(xt∣x<t)P(x_t \mid x_{<t})P(xt​∣x<t​)。但注意力的得分矩阵是全连接的——每个位置能看到所有位置，包括”未来”。若不加以限制，训练时模型会直接”抄答案”（用下一个词预测自己），损失趋近于零却毫无生成能力。

解决办法是在 softmax 之前，把得分矩阵上三角（未来位置）置为 −∞-\infty−∞，即因果掩码（causal mask）：

Sij′={sij/dk,j≤i−∞,j>iS'_{ij} = \begin{cases} s_{ij} / \sqrt{d_k}, & j \le i \\ -\infty, & j > i \end{cases}Sij′​={sij​/dk​​,−∞,​j≤ij>i​

softmax 后 exp⁡(−∞)=0\exp(-\infty) = 0exp(−∞)=0，未来位置的权重严格为零。这个 n×nn \times nn×n 的下三角布尔掩码只需构造一次，可以缓存复用。

另一个用途是填充掩码（padding mask）：批内不同句子长度不一时，把填充位置的得分也置 −∞-\infty−∞，避免污染注意力。

3.4.1 训练并行、推理自回归

因果掩码让 GPT 训练时可以一次前向计算所有位置的损失（teacher forcing，即”教师”把真实前文喂给模型而不是模型自己生成的文本，训练始终以真实数据为条件），完美并行；推理时则逐 token 生成——每生成一个 token 就把它拼回输入再前向。这引出 KV cache（第 14 章详解）：由于 K、V 只依赖历史 token，已算过的可以缓存，每步只需计算新 token 的 Query。

📌 注：teacher forcing 一词借自 RNN 时代的教学惯例：训练时每一步的条件是真实的前缀而非模型自己的输出。它带来训练（并行、条件干净）与推理（条件里含有模型自己生成的 token，可能有错）之间的分布差异，即”exposure bias”问题，这也是第 13 章对齐阶段要在模型自身样本上重新评估对数概率的原因之一。参见维基百科 Teacher forcing。

把训练与推理的计算量对比一下，能看清自回归的成本结构。训练时一次前向处理整个长度为 nnn 的序列，每个 token 都产生梯度信号，计算密度极高；推理时生成 nnn 个 token 需要 nnn 次前向，若无 KV cache 每次都要重算全部历史，总计算量为 ∑t=1nt⋅O(d2)=O(n2d2)\sum_{t=1}^{n} t \cdot O(d^2) = O(n^2 d^2)∑t=1n​t⋅O(d2)=O(n2d2)；有 KV cache 时每次只算一个新 token 的 Q 与全部 K/V 的交互，降为 O(n⋅d2)O(n \cdot d^2)O(n⋅d2)。这就是为什么一切推理优化的第一步都是实现 KV cache——它把生成复杂度从平方降到线性，且不改任何数学语义。

3.4.2 交叉注意力一瞥

原始 Transformer 的解码器里还有第二种掩码语义：交叉注意力（cross-attention）中，Query 来自解码器，而 Key/Value 来自编码器的输出，因此不需要因果掩码（编码器输出对解码器全程可见），但保留 padding mask。理解这一点有助于看清”因果掩码约束的是同一序列内部的时间方向”，而跨序列注意力（翻译、多模态中视觉 token 到语言 token 的注入，第 16 章 LLaVA 的投影连接可视为其退化形式）则由信息流向决定是否需要掩码。

3.5 位置编码

注意力本身是置换不变的：打乱输入 token 顺序，注意力只是相应地重排输出，无法区分”猫追狗”和”狗追猫”。因此必须显式注入位置信息。

3.5.1 正弦位置编码

原始 Transformer 对第 pospospos 个位置、第 iii 对维度使用不同频率的正弦/余弦：

3.5.2 可学习位置编码

GPT-2 直接把位置嵌入做成可学习的 nn.Embedding(max_len, d)。简单有效，成为早期 GPT 系列标准做法；缺点是不能自然外推到训练长度之外，且与 token 嵌入相加的方式使位置与语义信息糅合。

3.5.3 旋转位置编码 RoPE（重点推导）

RoPE（Rotary Position Embedding，arXiv:2104.09864）是当前主流（Llama、Qwen、DeepSeek 等）。核心思想：用旋转矩阵把绝对位置作用于 Q 和 K，而 Q 与 K 的内积自然只依赖相对位置。

复数视角。把第 mmm 个位置的查询向量 qqq 的第 iii 对分量 (q2i−1,q2i)(q_{2i-1}, q_{2i})(q2i−1​,q2i​) 视为复数 q(i)=q2i−1+i q2iq^{(i)} = q_{2i-1} + \mathrm{i}\, q_{2i}q(i)=q2i−1​+iq2i​。定义旋转：

q~m(i)=q(i)eimθi,θi=10000−2i/d\tilde{q}_m^{(i)} = q^{(i)} e^{\mathrm{i} m \theta_i}, \qquad \theta_i = 10000^{-2i/d}q~​m(i)​=q(i)eimθi​,θi​=10000−2i/d

关键结论：得分只依赖相对位置 m−nm - nm−n，与绝对位置 mmm、nnn 各自为何无关。旋转编码因此兼具”绝对形式、相对性质”——实现上按绝对位置旋转，数学上表达相对距离。

实数视角（矩阵形式）。等价地，每对相邻维度做一个二维旋转：

(q~2i−1q~2i)=(cos⁡mθi−sin⁡mθisin⁡mθicos⁡mθi)(q2i−1q2i)\begin{pmatrix} \tilde{q}_{2i-1} \\ \tilde{q}_{2i} \end{pmatrix} = \begin{pmatrix} \cos m\theta_i & -\sin m\theta_i \\ \sin m\theta_i & \cos m\theta_i \end{pmatrix} \begin{pmatrix} q_{2i-1} \\ q_{2i} \end{pmatrix}(q~​2i−1​q~​2i​​)=(cosmθi​sinmθi​​−sinmθi​cosmθi​​)(q2i−1​q2i​​)

相对位置性质。由上式，q~m⊤k~n\tilde{q}_m^\top \tilde{k}_nq~​m⊤​k~n​ 只含 m−nm-nm−n，位置每增加 1，相当于在所有频率上多旋转一个角度。这使得模型对”距离”的建模平移不变：两个 token 相隔 5 步的交互模式在任何上下文位置都一致。

实现（分块形式，避免逐对循环）：

def rope(x, theta_base=10000.0):           # x: (B, H, T, d_k)
    T, d = x.shape[-2], x.shape[-1]
    inv_freq = 1.0 / (theta_base ** (torch.arange(0, d, 2).float() / d))  # (d/2,)
    t = torch.arange(T).float()                       # 位置 (T,)
    freqs = torch.outer(t, inv_freq)                   # (T, d/2)
    cos, sin = freqs.cos(), freqs.sin()
    x1, x2 = x[..., 0::2], x[..., 1::2]                # 奇偶分块
    out = torch.empty_like(x)
    out[..., 0::2] = x1 * cos - x2 * sin              # 二维旋转
    out[..., 1::2] = x1 * sin + x2 * cos
    return out

只旋转 Q、K，不旋转 V。RoPE 的外推问题（训练 4K、推理 128K 时高频分量剧烈旋转）催生了 NTK-aware 缩放、YaRN 等外推方法（第 14 章）。

3.5.4 ALiBi 简述

ALiBi（Attention with Linear Biases）不走嵌入路线，直接在注意力得分上加线性惩罚：

sij←sij−∣i−j∣⋅mhs_{ij} \leftarrow s_{ij} - |i - j| \cdot \frac{m}{h}sij​←sij​−∣i−j∣⋅hm​

其中 mmm 是随头数递减的斜率（如 2−8h/H2^{-8h/H}2−8h/H）。距离越远惩罚越大，无需任何位置参数，外推性能好，被 BLOOM、MPT 等采用。与 RoPE 的区别：ALiBi 是加性偏置（作用于得分），RoPE 是乘性旋转（作用于 Q/K 向量本身）。

3.7.3 Post-LN vs Pre-LN

  • Post-LN（原始 Transformer）：x←LN(x+Sublayer(x))x \leftarrow \mathrm{LN}(x + \mathrm{Sublayer}(x))x←LN(x+Sublayer(x))，LN 在残差相加之后。梯度需穿过每层的 LN，深模型训练不稳定，必须配 warmup。
  • Pre-LN（GPT-2 起）：x←x+Sublayer(LN(x))x \leftarrow x + \mathrm{Sublayer}(\mathrm{LN}(x))x←x+Sublayer(LN(x))，LN 在子层之前。主干上是一条无阻隔的”恒等高速路”，梯度可直接回传，训练稳定得多，可省去 warmup；代价是层数很深时表征可能欠规范化。
  • 进一步的 Sandwich LN / Pre-LN + 最终 LN（Llama：每层 Pre-RMSNorm，模型末端再加一个 RMSNorm）是当前主流。

残差连接（residual connection）y=x+F(x)y = x + F(x)y=x+F(x) 并非 Transformer 原创，但至关重要。从反向传播看：

其中的”111”意味着无论子层 FFF 学到什么，梯度都有一条直通恒等路径回传。对 LLL 层堆叠的模型，梯度包含 ∏l(1+∂Fl/∂xl)\prod_l (1 + \partial F_l / \partial x_l)∏l​(1+∂Fl​/∂xl​) 的展开式，恒等项保证总有一个不衰减的成分，缓解了深层网络的梯度消失。这使堆叠上百层成为可能（ResNet 的核心洞察在 Transformer 中同样成立）。

  • GQA（grouped-query attention）：折中方案，把 hhh 个 Q 头分成 ggg 组，每组共享一套 K/V（Llama-3-70B：64 个 Q 头、8 组 KV 头，KV cache 缩小 8 倍）。
  • MLA（multi-head latent attention，DeepSeek-V2/V3）：把 KV 压缩到低秩潜在向量再按需还原，KV cache 缩小一个数量级，同时保持质量（第 14 章再述）。

表中的其他演进也有清晰的成本-收益逻辑：去掉偏置（Llama 起几乎删光 bias）是因为 LN 之后偏置作用微弱、却增加访存与 kernel 开销；扩大词表（32K → 128K+）以嵌入参数为代价换取多语言压缩率，配合 15T 级 token 的训练量摊薄成本；BF16 替代 FP16 则纯粹为了训练数值稳定（第 6 章）。可以看到，现代架构设计的主旋律不是”发明新结构”，而是在多年消融实验沉淀下的候选组件中，按训练规模做预算最优的组合——这背后正是第 7 章 Scaling Laws 的方法论。

3.11 逐模块 PyTorch 实现：150 行最小 GPT

下面实现一个完整可运行的 decoder-only GPT（结构对齐 GPT-2 风格，Pre-LN）。依赖仅 torch。

3.11.1 模型组件

import math
import torch
import torch.nn as nn
import torch.nn.functional as F

class CausalSelfAttention(nn.Module):
    """多头因果自注意力（Pre-LN 下使用）"""
    def __init__(self, d_model, n_head, dropout=0.1, max_len=1024):
        super().__init__()
        assert d_model % n_head == 0
        self.n_head, self.d_k = n_head, d_model // n_head
        self.qkv = nn.Linear(d_model, 3 * d_model)   # Q/K/V 一次投影
        self.proj = nn.Linear(d_model, d_model)      # 输出投影 W_O
        self.attn_drop = nn.Dropout(dropout)
        self.resid_drop = nn.Dropout(dropout)
        mask = torch.tril(torch.ones(max_len, max_len, dtype=torch.bool))
        self.register_buffer("mask", mask.view(1, 1, max_len, max_len))

    def forward(self, x):
        B, T, C = x.shape
        q, k, v = self.qkv(x).split(C, dim=2)
        # (B,T,C) -> (B, n_head, T, d_k)
        q = q.view(B, T, self.n_head, self.d_k).transpose(1, 2)
        k = k.view(B, T, self.n_head, self.d_k).transpose(1, 2)
        v = v.view(B, T, self.n_head, self.d_k).transpose(1, 2)
        att = (q @ k.transpose(-2, -1)) / math.sqrt(self.d_k)   # (B,H,T,T)
        att = att.masked_fill(~self.mask[:, :, :T, :T], float("-inf"))  # 因果掩码
        att = F.softmax(att, dim=-1)
        y = self.attn_drop(att) @ v                             # (B,H,T,d_k)
        y = y.transpose(1, 2).contiguous().view(B, T, C)        # 拼接多头
        return self.resid_drop(self.proj(y))

class MLP(nn.Module):
    """前馈网络：GELU 激活，隐藏维 4d（若换 SwiGLU 则取 8/3d）"""
    def __init__(self, d_model, dropout=0.1):
        super().__init__()
        self.fc = nn.Linear(d_model, 4 * d_model)
        self.proj = nn.Linear(4 * d_model, d_model)
        self.drop = nn.Dropout(dropout)

    def forward(self, x):
        return self.drop(self.proj(F.gelu(self.fc(x))))

class Block(nn.Module):
    """Pre-LN Transformer 块：x + Attn(LN(x))，然后 x + MLP(LN(x))"""
    def __init__(self, d_model, n_head, dropout=0.1):
        super().__init__()
        self.ln1 = nn.LayerNorm(d_model)
        self.attn = CausalSelfAttention(d_model, n_head, dropout)
        self.ln2 = nn.LayerNorm(d_model)
        self.mlp = MLP(d_model, dropout)

    def forward(self, x):
        x = x + self.attn(self.ln1(x))   # 残差 + 注意力子层
        x = x + self.mlp(self.ln2(x))    # 残差 + FFN 子层
        return x

3.11.2 顶层模型与生成

class GPT(nn.Module):
    def __init__(self, vocab_size, d_model=384, n_head=6,
                 n_layer=6, block_size=256, dropout=0.1):
        super().__init__()
        self.block_size = block_size
        self.tok_emb = nn.Embedding(vocab_size, d_model)   # token 嵌入
        self.pos_emb = nn.Embedding(block_size, d_model)   # 可学习位置嵌入
        self.drop = nn.Dropout(dropout)
        self.blocks = nn.ModuleList(
            [Block(d_model, n_head, dropout) for _ in range(n_layer)])
        self.ln_f = nn.LayerNorm(d_model)                  # 末端归一化
        self.head = nn.Linear(d_model, vocab_size, bias=False)
        self.apply(self._init_weights)                     # 权重初始化

    def _init_weights(self, m):
        if isinstance(m, nn.Linear):
            nn.init.normal_(m.weight, mean=0.0, std=0.02)  # GPT-2 式小方差初始化
            if m.bias is not None:
                nn.init.zeros_(m.bias)
        elif isinstance(m, nn.Embedding):
            nn.init.normal_(m.weight, mean=0.0, std=0.02)

    def forward(self, idx, targets=None):
        B, T = idx.shape
        assert T <= self.block_size, "序列超长"
        pos = torch.arange(T, device=idx.device)
        x = self.drop(self.tok_emb(idx) + self.pos_emb(pos))
        for blk in self.blocks:
            x = blk(x)
        x = self.ln_f(x)
        logits = self.head(x)                              # (B,T,vocab)
        loss = None
        if targets is not None:
            loss = F.cross_entropy(
                logits.view(-1, logits.size(-1)), targets.view(-1))
        return logits, loss

    @torch.no_grad()
    def generate(self, idx, max_new_tokens=100, temperature=1.0, top_k=None):
        """自回归生成：逐 token 预测并拼回输入"""
        for _ in range(max_new_tokens):
            idx_cond = idx[:, -self.block_size:]            # 截断到上下文窗口
            logits, _ = self(idx_cond)
            logits = logits[:, -1, :] / temperature         # 只取最后一步
            if top_k is not None:                           # top-k 采样
                v, _ = torch.topk(logits, top_k)
                logits[logits < v[:, [-1]]] = float("-inf")
            probs = F.softmax(logits, dim=-1)
            idx_next = torch.multinomial(probs, num_samples=1)
            idx = torch.cat([idx, idx_next], dim=1)         # 拼接回输入
        return idx

if __name__ == "__main__":
    torch.manual_seed(0)
    model = GPT(vocab_size=1000)
    x = torch.randint(0, 1000, (2, 32))                     # (batch, seq)
    logits, loss = model(x, targets=x.roll(-1, dims=1))     # 简单自监督示例
    print("参数量:", sum(p.numel() for p in model.parameters()))
    print("损失:", loss.item())

实现要点逐条说明：

  1. QKV 合并投影：一个 Linear(d, 3d) 再 split，比三个矩阵各调一次更高效；多头切分用 view + transpose 而非真复制。
  2. 掩码注册为 buffer：register_buffer 使掩码随模型移动设备且不计入参数；tril 生成下三角，~mask 处填 −∞-\infty−∞。
  3. Pre-LN：两个子层各自先过 LN，残差主干保持畅通（3.7.3 节）；末端再补一个 ln_f。
  4. 初始化：GPT-2 用 N(0,0.02)\mathcal{N}(0, 0.02)N(0,0.02) 初始化线性与嵌入层，配合残差结构足够稳定；更深的模型需额外缩放（如残差投影按 1/2L1/\sqrt{2L}1/2L​）。
  5. generate 的温度与 top-k：除以温度控制随机性，top-k 截断长尾（第 2 章已讨论采样策略）。
  6. x.roll(-1)：训练目标是右移一位的输入本身；实际训练请用第 4 章的分词器与正确的标签构造（targets = ids[:, 1:] 配 logits[:, :-1]）。

3.12.2 训练 FLOPs：6ND6ND6ND 的推导

前向传播中，参数量为 NNN 的模型，每个参数对应输入上约一次乘加（一个 d×dd \times dd×d 矩阵乘对每 token 恰好用每个参数一次），故每 token 前向 FLOPs ≈2N\approx 2N≈2N（一次乘 + 一次算 2 FLOPs）。

反向传播需要计算对输入和对权重两组梯度，计算量约为前向的 2 倍：每 token 反向 ≈4N\approx 4N≈4N。

总训练计算量（DDD 为训练 token 数）：

C≈2ND⏟前向+4ND⏟反向=6NDC \approx \underbrace{2ND}_{\text{前向}} + \underbrace{4ND}_{\text{反向}} = 6NDC≈前向2ND​​+反向4ND​​=6ND

例：Llama-2 7B 训练 2T token：6×6.7×109×2×1012≈8×10226 \times 6.7 \times 10^9 \times 2 \times 10^{12} \approx 8 \times 10^{22}6×6.7×109×2×1012≈8×1022 FLOPs，与论文报告的 8.4×10228.4 \times 10^{22}8.4×1022 吻合。注意注意力得分矩阵的计算 O(n2d)O(n^2 d)O(n2d) 在长序列时是额外项，上式忽略之（短序列时占比小）。

3.12.3 KV cache 显存公式（预告）

推理时缓存每层所有历史 token 的 K 与 V。对层数 LLL、KV 头数 hkvh_{kv}hkv​（GQA 下小于 hhh）、头维 dkd_kdk​、序列长 nnn、batch BBB、每个元素 ppp 字节（FP16 为 2）：

KV cache=2×L×hkv×dk×n×B×p\text{KV cache} = 2 \times L \times h_{kv} \times d_k \times n \times B \times pKV cache=2×L×hkv​×dk​×n×B×p

例：Llama-2-7B（L=32L{=}32L=32，hkv=32h_{kv}{=}32hkv​=32，dk=128d_k{=}128dk​=128），FP16、batch 1、n=4096n{=}4096n=4096：2×32×32×128×4096×2≈2.12 \times 32 \times 32 \times 128 \times 4096 \times 2 \approx 2.12×32×32×128×4096×2≈2.1 GB——batch 1 就要 2 GB，再乘以并发数很容易吃满显存。三个缓解手段与该公式一一对应：缩 hkvh_{kv}hkv​（GQA：Llama-2-70B 取 hkv=8h_{kv}=8hkv​=8，直接省 8 倍；MLA 用低秩压缩省得更多）、缩 ppp（KV cache 量化到 INT8 甚至 FP4，第 14 章）、缩 nnn（滑动窗口注意力等）。注意 KV cache 与 batch、序列长度的乘积关系也解释了为什么长上下文服务的并发能力骤降——这是第 15 章显存容量规划的核心约束。

3.13 常见误区辨析

初学者实现 Transformer 时最容易踩的坑，在此集中列出：

  1. 忘记除以 dk\sqrt{d_k}dk​​。小数据集上往往”也能训”，掩盖了 softmax 饱和问题；数据一大 loss 就不动了。缩放因子必须与每头维度 dkd_kdk​ 对应，而不是 dmodeld_{\text{model}}dmodel​。
  2. 多头切分用错维度。view(B, T, H, d_k) 后必须 transpose(1, 2) 把头维提前，否则”多头”退化成对特征维的错误分组；拼接时记得 contiguous().view(B, T, C)。
  3. 掩码方向搞反。因果掩码是下三角可见（tril），填 −∞-\infty−∞ 的位置是”未来”。调试时打印一行权重，应看到位置 ttt 之后全为 0。
  4. Pre-LN 与 Post-LN 的层归一化位置写混，或漏掉末端 ln_f。
  5. RoPE 只旋转 Q/K，不旋转 V；且推理时缓存的历史 K 必须在缓存前就完成旋转，否则每步的坐标系不一致。
  6. 训练目标与输入错位：标签必须是右移一位的序列，logits[:, :-1] 对 targets = ids[:, 1:]，直接拿 ids 当自己的标签会让模型学到恒等映射且损失虚低。

本章小结

  • RNN 的顺序计算与长程梯度衰减催生了注意力：所有位置两两直接交互，一次矩阵乘法完成。
  • 缩放点积注意力 softmax(QK⊤/dk)V\mathrm{softmax}(QK^\top/\sqrt{d_k})Vsoftmax(QK⊤/dk​​)V；除以 dk\sqrt{d_k}dk​​ 是因为独立分量点积的方差为 dkd_kdk​，不缩放会使 softmax 饱和、梯度消失。复杂度 O(n2d)O(n^2 d)O(n2d)，长序列平方膨胀是主要瓶颈。
  • 多头注意力以零额外参数代价在多个子空间学习不同交互模式。
  • 因果掩码把未来位置得分置 −∞-\infty−∞，使训练可并行、推理可自回归。
  • 位置信息必须显式注入：正弦编码免学习、可学习编码简单、RoPE 用旋转把绝对位置编码进 Q/K 而内积只依赖相对位置，是当前标准；ALiBi 用线性距离惩罚替代。
  • FFN 占参数大头，激活从 ReLU→GELU→SwiGLU，SwiGLU 三矩阵因此隐藏维取 ≈83d\approx \frac{8}{3}d≈38​d 以对齐参数预算。
  • 归一化从 Post-LN 演进到 Pre-RMSNorm，配合残差恒等路径，让百层模型可训。
  • 架构上 decoder-only 胜出；GPT-2 到 Llama 的演进主线：RMSNorm、RoPE、SwiGLU、GQA、无 bias、大词表。
  • 估算工具箱：参数 N≈12Ld2+2VdN \approx 12Ld^2 + 2VdN≈12Ld2+2Vd；训练 FLOPs C=6NDC = 6NDC=6ND；KV cache =2LhkvdknBp= 2Lh_{kv}d_k n B p=2Lhkv​dk​nBp 字节。

实操：编程练习

练习 A：从零实现缩放点积注意力，并与官方实现对账。 用 3.2.3 节手算例子的思想，写一个支持（可选）因果掩码的注意力，数值验证与 torch.nn.functional.scaled_dot_product_attention 完全一致。

import torch
import torch.nn.functional as F
import math

def attention(Q, K, V, causal=False):
    """朴素实现：Q,K,V: (B, H, T, d_k) -> (B, H, T, d_k)"""
    d_k = Q.size(-1)
    att = Q @ K.transpose(-2, -1) / math.sqrt(d_k)        # (B,H,T,T) 缩放点积
    if causal:                                            # 上三角(未来)置 -inf
        T = Q.size(-2)
        mask = torch.tril(torch.ones(T, T, dtype=torch.bool, device=Q.device))
        att = att.masked_fill(~mask, float("-inf"))
    return F.softmax(att, dim=-1) @ V

torch.manual_seed(0)
Q, K, V = (torch.randn(2, 4, 8, 16) for _ in range(3))     # B=2, H=4, T=8, d_k=16
out_naive = attention(Q, K, V, causal=True)
out_official = F.scaled_dot_product_attention(Q, K, V, is_causal=True)
print("max |diff| =", (out_naive - out_official).abs().max().item())
# 预期输出：max |diff| ≈ 1e-6 量级（浮点误差内），两实现等价
# 官方版本内部会自动选择 FlashAttention 等 kernel——数学相同、显存与速度更优

练习 B：数值验证因果掩码”看不见未来”。 对比有/无因果掩码时各位置的输出：无掩码时改变未来 token 会影响历史位置的输出，有掩码时则完全不受影响。

import torch, torch.nn.functional as F, math

torch.manual_seed(0)
Q, K, V = (torch.randn(1, 1, 6, 8) for _ in range(3))      # T=6, d_k=8

def attn(Q, K, V, causal):
    att = Q @ K.transpose(-2, -1) / math.sqrt(Q.size(-1))
    if causal:
        T = Q.size(-2)
        att = att.masked_fill(
            ~torch.tril(torch.ones(T, T, dtype=torch.bool)), float("-inf"))
    return F.softmax(att, dim=-1) @ V

K2, V2 = K.clone(), V.clone()
K2[0, 0, 2] += 10.0                                        # 篡改"未来"(位置2)
V2[0, 0, 2] += 10.0

out_a, out_b = attn(Q, K, V, causal=True), attn(Q, K2, V2, causal=True)
diff_causal = (out_a[0, 0, :2] - out_b[0, 0, :2]).abs().max().item()
print(f"因果掩码下，位置0/1 输出受未来篡改影响: {diff_causal:.2e}")  # 预期 0.00e+00

out_c, out_d = attn(Q, K, V, causal=False), attn(Q, K2, V2, causal=False)
diff_full = (out_c[0, 0, :2] - out_d[0, 0, :2]).abs().max().item()
print(f"无掩码时，位置0/1 输出受未来篡改影响: {diff_full:.3f}")     # 预期 > 0（未来泄漏）

练习 C：用 autograd 验证注意力反向传播。 3.2.3 节末提到 ∂L/∂V=A⊤(∂L/∂O)\partial L/\partial V = A^\top(\partial L/\partial O)∂L/∂V=A⊤(∂L/∂O)、且 softmax 梯度为 aij(1−aij)a_{ij}(1-a_{ij})aij​(1−aij​)。用 PyTorch 的自动微分数值确认这两条性质。

import torch, torch.nn.functional as F, math

torch.manual_seed(0)
Q = torch.eye(2)                                    # 复用 3.2.3 节 2×2 手算例子
K = torch.eye(2).requires_grad_(True)
V = torch.tensor([[1., 2.], [3., 4.]], requires_grad=True)

S = Q @ K.T / math.sqrt(2)
A = F.softmax(S, dim=-1)                            # 权重矩阵 A
O = A @ V
G = torch.tensor([[1., 0.], [0., 1.]])              # 假设 dL/dO = I
O.backward(G)

print("A =", A)                                     # 预期 [[0.670,0.330],[0.330,0.670]]
print("解析解 AᵀG =", (A.T @ G))                     # ∂L/∂V 的解析式
print("autograd  ∂L/∂V =", V.grad)                   # 两者应逐元素相等
assert torch.allclose(V.grad, A.T @ G, atol=1e-6)
# 再验证 softmax 梯度：p(1-p)。对第 1 行 logit (0.707, 0)，p0 = 0.670
a = torch.tensor(0.707, requires_grad=True)
torch.softmax(torch.stack([a, torch.tensor(0.)]), 0)[0].backward()
print(f"softmax 梯度 = {a.grad:.4f} (期望 ≈ {0.670*(1-0.670):.4f})")  # ≈ 0.221
