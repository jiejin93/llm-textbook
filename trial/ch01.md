# 第 1 章 绪论：大语言模型全景

2022 年 11 月底，ChatGPT 上线，五天收获一百万用户，两个月月活过亿——这个速度超过了此前所有消费级互联网产品。人们突然意识到：一个只被训练来"预测下一个词"的神经网络，竟能写代码、做翻译、解数学题、进行多轮对话。这场变革并非一夜发生，而是近四十年语言建模技术持续演进、并在"规模"（scale）的杠杆下发生质变的结果。

本章是全书的开篇，目标有三个：第一，建立对"什么是大语言模型"的准确直觉——下一 token 预测（next-token prediction）范式为何威力巨大，什么是能力涌现；第二，梳理从 n-gram 到 DeepSeek 的发展脉络，让你在读到后续章节的每个技术时都知道"它从哪里来、解决什么问题"；第三，给出全书路线图并搭好学习环境。学完本章，你应当能够在一张白纸上画出 LLM 的"预训练—微调—对齐"三级流水线，并对参数、数据、算力三者的规模量级有基本感觉。

## 1.1 什么是大语言模型

### 1.1.1 语言建模：从概率到生成

语言模型（Language Model, LM）的本质，是对自然语言的概率分布建模：给定一段文本，计算这段文本出现的概率。用形式化语言描述，设一个长度为 $T$ 的词序列 $w = (w_1, w_2, \dots, w_T)$，语言模型给出其联合概率 $P(w_1, \dots, w_T)$。直接建模联合概率很困难，概率链式法则（chain rule of probability）告诉我们，可以把它分解为一系列条件概率的连乘：

$$P(w_1, w_2, \dots, w_T) = \prod_{t=1}^{T} P(w_t \mid w_1, \dots, w_{t-1})$$

也就是说，"建模一段话的概率"等价于"反复预测下一个词"。这就是**自回归（autoregressive）语言建模**：每次以已生成的全部前文为条件，预测下一个 token 的概率分布 $P(w_t \mid w_{<t})$。大语言模型就是用极深的神经网络（在本书中几乎总是 Transformer）来实现这个条件分布的模型，"大"指的是参数量大——现代 LLM 从数十亿（B，billion）到上万亿参数不等。

"预测下一个词"这个目标看似简单，实则是通用的：要把下一个词预测得准，模型隐式地必须掌握语法、事实知识、常识推理，甚至代码逻辑。例如，要预测"法国的首都是__"的下一个词，模型必须"知道"巴黎；要预测一段 Python 代码的下一个 token，模型必须"理解"缩进规则与变量作用域。下一 token 预测因此被称为一种**自监督学习**（self-supervised learning）：监督信号（下一个词是什么）直接来自数据本身，无需人工标注，这使得训练数据可以扩展到互联网规模的万亿 token。

> 📌 注：本节用"词"（word）称呼序列单元 $w_t$，是为了让链式法则的记号与第 0 章概率部分保持一致。在实际系统中，模型处理的最小单位是 **token**——由分词器（第 4 章）切出的子词片段，可能是整词（"学习"）、词的一部分（"ization"）或单个字节。本书第 2 章之后会逐渐统一使用 token 记号，两者的数学角色完全相同：都是离散词表 $V$ 中的一个元素。更多背景可参考维基百科 [Word (computing) 与 token 化](https://en.wikipedia.org/wiki/Large_language_model)。

生成（generation）则是在训练好的模型上反复执行：采样一个 token，拼回输入，再预测下一个，循环往复。这个"一次预测一个、喂回去再预测"的过程称为**自回归解码**（autoregressive decoding），是第 14 章推理优化的核心对象。

### 1.1.2 能力涌现：规模的魔法

一个令人惊讶的经验现象是：许多能力并非随规模线性增长，而是在参数量跨过某个阈值后才**突然出现**，这就是**涌现能力**（emergent abilities）。Wei et al.（2022）系统报告了这一现象：在数十亿参数以下，模型做多位数加法的正确率接近随机；跨过阈值后，正确率陡然跃升。类似地，思维链（Chain-of-Thought, CoT） prompting 带来的推理增益，也主要出现在百亿参数以上的模型中。

对涌现现象的解释存在争议。一种观点（Schaeffer et al., 2023）认为，部分"涌现"是评测指标非线性（如"完全答对才得分"的离散指标）造成的假象，换成连续指标后能力增长其实是平滑的。

> 📌 注：如果你对"规模变大为什么会产生质变"缺少直觉，可以把下一 token 预测想象成无数个难度不一的子任务（拼词、搭配、事实、推理）的混合：小模型把算力花在最常见的子任务上，长尾任务的表现停留在随机水平，因此在"完全答对才得分"的指标上得分接近零；规模扩大后长尾任务陆续越过随机基线，宏观上就表现为"突然会了"。想看更直观的可视化讲解，推荐 3Blue1Brown 的 [Deep Learning 系列视频（第 5 章：注意力与 Transformer）](https://www.3blue1brown.com/topics/neural-networks)。

本书第 7 章将回到这一争论。无论解释如何，工程事实是清楚的：**规模本身是能力的重要来源**，参数量、数据量、算力三者需要协同扩展——这正是 Scaling Laws（规模定律）研究的对象，也是现代 LLM 区别于传统 NLP 模型的根本特征。

### 1.1.3 LLM 与传统 NLP 模型的区别

下表概括了范式层面的关键差异：

| 维度 | 传统 NLP（BERT 时代） | 大语言模型（GPT 时代） |
| --- | --- | --- |
| 训练目标 | 掩码词预测等代理任务 | 下一 token 预测 |
| 任务适配 | 每个任务一个微调头 | 一个模型通吃，提示词即可 |
| 交互方式 | 分类/打分 | 自然语言指令 + 生成 |
| 规模 | 1 亿参数量级（如 BERT-base 110M） | 10B 至万亿参数 |
| 数据 | 数十 GB 精选语料（如 BookCorpus + Wikipedia） | 数万亿 token 的网络级语料 |

值得强调的是"一个模型通吃"带来的产品形态变化：过去为情感分析、命名实体识别、机器翻译分别训练模型；今天只需向同一个 LLM 描述任务（few-shot prompting），它便可根据示例推断意图。任务边界从"模型结构 + 数据集"转移到了"提示词"，这是 ChatGPT 能成为通用助手的技术前提。

### 1.2.1 统计时代：n-gram 与香农的游戏

1948 年，香农（Claude Shannon）在《通信的数学理论》中提出用 n-gram 统计来逼近英语的熵，并设计了著名的"人类预测下一个字母"实验。此后数十年，基于计数和平滑（smoothing）的 n-gram 模型一直是语音识别与机器翻译的标准组件。它的根本缺陷在第 2 章会详细讨论：稀疏性——绝大多数合法的词组合在训练数据中从未出现，参数量随阶数指数增长，长程依赖无从谈起。

### 1.2.2 神经时代：从 NNLM 到 RNN/LSTM

2003 年，Bengio 等人的神经概率语言模型（Neural Probabilistic Language Model, NNLM）迈出关键一步：用神经网络的词嵌入（word embedding）表示词，再把前 $n-1$ 个词的嵌入拼接后经多层网络预测下一个词。这一工作引入了两个影响深远的思想——**分布式词表示**与**参数共享**，使模型能对未见过的词组合给出合理的概率泛化。2013 年 word2vec 把"分布式表示"推向极致，2014 年 Seq2Seq 与注意力机制（attention，最初作为 RNN 翻译系统的对齐组件）登场。RNN/LSTM 虽能处理任意长度序列，但其顺序计算无法并行、且长距离信息经反复传递容易衰减，制约了规模扩展——这两个痛点正是 Transformer 的直接靶子。

### 1.2.3 规模时代：Transformer 与 GPT 系列

2017 年，Google 的《Attention Is All You Need》提出 Transformer：抛弃循环结构，完全依靠自注意力（self-attention）在任意两个位置之间直接传递信息，训练可完全并行。Transformer 是现代所有 LLM 的骨架，第 3 章将逐模块剖析。

2018–2020 年，GPT 系列验证了"Transformer 解码器 + 大规模下一词预测"路线的威力：

- **GPT-1**（2018，1.17 亿参数）：首次展示"无监督预训练 + 有监督微调"的两段式范式，在多个 NLP 任务上达到当时最优。
- **GPT-2**（2019，15 亿参数）：发现规模扩大后，模型无需微调即可通过零样本提示（zero-shot prompting）完成多任务，于是"通用语言模型"的构想开始成形。
- **GPT-3**（2020，1750 亿参数，约 3000 亿 token 训练）：参数量扩大百倍以上后，**上下文学习**（in-context learning）出现——在提示里给几个示例，模型就能照做新任务，无需更新任何权重。GPT-3 的论文标题直接点题："Language Models are Few-Shot Learners"。

### 1.2.4 对齐时代：InstructGPT 与 ChatGPT

GPT-3 虽强，却像一个"文献续写器"而非"助手"：用户问它问题，它可能接着写"还有人问……"而不是回答。2022 年初的 InstructGPT（Ouyang et al., 2022）给出解法，确立了**RLHF**（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）三阶段流程：先监督微调（SFT）教会模型遵循指令，再训练奖励模型（RM）为回答打分，最后用强化学习（PPO）优化模型去最大化奖励。ChatGPT 正是这套配方的产品化，RLHF 让"续写器"变成了"对话助手"。此后 DPO、GRPO 等更简洁的对齐方法相继出现，2025 年初 DeepSeek-R1 展示了用 GRPO + 可验证奖励（RLVR）就能激发出长链推理能力，把后训练推向了新阶段。这些将在第 12–13 章完整展开。

### 1.2.5 开源浪潮：Llama、Qwen 与 DeepSeek

GPT-3 之后，开源社区从追赶到并跑。Meta 的 **Llama**（2023.2，7B–65B）与 **Llama 2**（2023.7，7B/13B/70B）确立了"开源权重 + 现代架构（RMSNorm、RoPE、SwiGLU、GQA）"的事实标准，Llama 3（2024.4，8B/70B，后续 405B）进一步缩小了与闭源模型的差距。同期 Mistral 7B（2023.9）以小胜大，Mixtral（2023.12）把混合专家（MoE）架构带入开源视野。国内的 **Qwen**（阿里通义千问）系列持续迭代，Qwen2.5 覆盖 0.5B–72B 并成为开源社区微调最频繁的基座之一；**DeepSeek-V3**（2024.12，671B 总参数、约 37B 激活的 MoE）以极低的训练成本引发关注，**DeepSeek-R1**（2025.1）则以开放权重复现了 o1 级别的推理能力。今天，一个开发者用一张消费级显卡就能运行 7B 级模型、用 LoRA 微调出自己的助手——这在 2020 年是不可想象的。

- **预训练（pre-training）**：在数万亿 token 上做下一词预测，学会语言、知识与初步推理。消耗了绝大部分算力（GPT-3 级模型训练一次需要数千张 GPU 跑数周），产出的是"基座模型"（base model）。
- **监督微调（Supervised Fine-Tuning, SFT）**：用人工编写的高质量"指令→回答"对继续训练，把基座从"续写机器"变成"听指令办事的模型"。数据量骤降至万级到百万级，算力需求小几个数量级。
- **对齐（alignment）**：通过人类偏好数据 + 强化学习，进一步塑造模型的行为边界——更有帮助、更诚实、更无害（Helpful, Honest, Harmless，即 3H）。SFT 教模型"做什么"，对齐在诸多可行回答中挑选"人类更偏好的那种"。

一个常见的误解是把三段流水线当作严格串行的"官方流程"。实践中它是灵活的：小模型可以直接蒸馏；RLHF 之后常再补一轮 SFT；DeepSeek-R1 甚至展示了"纯 RL（可验证奖励）+ 少量冷启动数据"也能造就强推理模型。但作为思维框架，"预训练给能力、微调给形式、对齐给价值观"是理解一切后训练技术的钥匙。

## 1.4 规模概览：参数、数据、算力

三个量级决定了 LLM 的成本与能力。下表列出若干代表性模型（数字来自各官方论文/技术报告，开源模型给出总参数量，MoE 模型注明激活参数）：

| 模型 | 发布时间 | 参数量 | 训练数据（token） | 备注 |
| --- | --- | --- | --- | --- |
| GPT-2 | 2019.02 | 1.5B | 约 40 亿（WebText） | 零样本多任务初现 |
| GPT-3 | 2020.05 | 175B | 约 3000 亿 | few-shot 学习，训练约 3.14e23 FLOPs |
| Llama 2 | 2023.07 | 7B / 13B / 70B | 2 万亿 | 开源权重，可商用 |
| Mistral 7B | 2023.09 | 7.3B | 8 万亿 | 滑动窗口注意力 |
| Mixtral 8x7B | 2023.12 | 46.7B（每 token 激活约 12.9B） | — | 开源 MoE 代表 |
| Llama 3 | 2024.04 | 8B / 70B（405B 于 2024.07） | 15 万亿+ | 开源旗舰 |
| Qwen2.5 | 2024.09 | 0.5B – 72B | 18 万亿 | 中文最强开源系之一 |
| DeepSeek-V3 | 2024.12 | 671B（激活约 37B） | 14.8 万亿 | MoE，报告训练约 2.788M H800 GPU 时 |

几点直觉值得建立：

- **参数量**：7B 级模型在 INT4 量化后约占 4 GB 存储，可塞进手机；70B 级需要多卡服务；671B 的 MoE 虽总参数巨大，但每个 token 只激活一小部分，推理成本远低于同参数量的稠密模型。
- **数据量**：经验上，训练 token 数与参数量的比值（"重复度"）在 Chinchilla 最优附近约为 20:1（第 7 章），但现代模型普遍远超此比例（Llama 3 为 15T/8B ≈ 1875:1），靠数据重复利用换取小参数高性能。
- **算力**：训练总计算量常用 $C \approx 6ND$ 估算（$N$ 为参数量，$D$ 为 token 数，第 3 章推导）。一张 H100 每秒约 $10^{15}$ FLOPs（BF16 理论峰值近 $10^{15}$），训练一个 8B 模型 15T token 约 $7.2\times10^{23}$ FLOPs——即便千卡集群也要跑数周。这个估算能力在第 7、8、15 章会反复用到。

### 1.4.1 算力之外的隐藏成本

初学者容易把 LLM 的门槛等同于"买得起多少张显卡"，实际上预训练还有三块常被低估的成本。**数据工程**：从 Common Crawl 到可训练语料需要经过抓取、抽取、清洗、去重、配比等长管线（第 5 章），其工程量与调参难度不亚于训练本身；业界常说"垃圾进、垃圾出"，数据质量的细微差异会在最终模型能力上被放大。**实验与迭代**：一次大规模预训练动辄数周，期间任何一次 loss spike 都可能浪费数十万元算力，因此必须先用小模型、短训练做充分的消融实验（这依赖第 7 章 Scaling Laws 提供的外推能力），再放大到目标规模。**评测**：训练完成只是开始，要回答"这个模型到底好不好、好在哪里、差在哪里"，需要系统化的评测体系（第 11 章）。理解这三块隐藏成本，有助于你在阅读本书后续章节时明白：为什么我们要花整整五章讲预训练，而不是只讲一个训练循环。

### 1.4.2 一个常见的规模误区

"参数越多越好"是新手最常见的误区。事实上，在固定算力预算下，参数量与数据量存在最优配比（Chinchilla 定律，第 7 章）：盲目堆参数而数据不足，模型会"欠训练"，性能反而不如更小但喂饱数据的模型。而在部署侧，推理成本几乎随参数量线性增长，第 14 章会展示同一模型的不同量化版本在精度与速度之间的权衡。**规模是一个三维（参数、数据、算力）联合优化问题，而不是一个单维军备竞赛**——DeepSeek-V3 用 671B 总参数、约 37B 激活的稀疏设计在成本与能力之间取得平衡，正是这一思想的好例子。

全书 17 章按"基础 → 预训练 → 微调评测 → 后训练 → 部署 → 多模态与前沿"推进（前言中的路线图给出了完整依赖关系）。就本章之后的路径而言：第 2 章补齐语言建模的概率基础与解码策略，第 3 章深入 Transformer 并亲手实现最小 GPT，第 4 章解决文本如何变成 token 的问题——这四章是全书的地基。此后无论你走向预训练工程（第 5–9 章）、微调与评测（第 10–11 章）、对齐研究（第 12–13 章）还是推理部署（第 14–15 章），都建立在这块地基之上。

## 本章小结

- 语言建模 = 用链式法则把序列概率分解为条件概率连乘，LLM 用超大神经网络实现 $P(w_t \mid w_{<t})$，即下一 token 预测；该目标自监督、可扩展，是能力涌现的土壤。
- 发展史的主旋律是"可扩展性"：n-gram 受稀疏性所限 → NNLM 引入分布式表示 → RNN 受顺序计算所限 → Transformer 实现全并行 → GPT-3 验证规模 → InstructGPT/ChatGPT 解决对齐 → Llama/Qwen/DeepSeek 开源浪潮。
- 现代 LLM 生产是三级流水线：预训练（能力，消耗绝大部分算力）→ SFT（指令形式）→ 对齐（偏好与安全）。
- 参数（B 级到千亿级）、数据（万亿 token 级）、算力（$C \approx 6ND$，e23–e25 FLOPs）三个数字是讨论一切 LLM 的坐标系。
- 环境准备：Python + PyTorch 2.x + HuggingFace 全家桶，无 GPU 可用 Colab / 国内云平台，下载用 hf-mirror 镜像。

### 实操：编程练习

**练习 A：用 pipeline 跑一个小模型问答。** HuggingFace 的 `pipeline` 是调用 LLM 的最短路径，先用它建立"模型—分词器—生成"的整体印象（各组件分别在第 3、4 章拆解）。

```python
# pip install transformers torch
from transformers import pipeline

# 文本生成 pipeline：加载一个 0.5B 小模型，CPU 也能跑（几分钟内下载完成）
# 国内可先执行: export HF_ENDPOINT=https://hf-mirror.com
gen = pipeline("text-generation", model="Qwen/Qwen2.5-0.5B")

prompt = "问题：法国的首都是哪里？\n答案："
out = gen(prompt, max_new_tokens=20, do_sample=False)  # do_sample=False 即贪心解码
print(out[0]["generated_text"])
# 预期输出（截断示意）：'问题：法国的首都是哪里？\n答案：巴黎。'
# 模型只见过"续写"，却回答了问题——第 1.1.1 节"下一词预测蕴含知识"的直接证据

# 换一个对话格式的 pipeline，体验指令模型与基座模型的区别
chat = pipeline("text-generation", model="Qwen/Qwen2.5-0.5B-Instruct")
msgs = [{"role": "user", "content": "用一句话解释什么是注意力机制。"}]
print(chat(msgs, max_new_tokens=60)[0]["generated_text"][-1]["content"])
```

**练习 B：亲手验证"续写器 vs 助手"。** 用同一个问题分别问基座模型与指令模型，观察 1.2.4 节描述的行为差异。

```python
from transformers import pipeline

base = pipeline("text-generation", model="Qwen/Qwen2.5-0.5B")
q = "北京有什么好玩的景点？"
print(base(q, max_new_tokens=50, do_sample=False)[0]["generated_text"])
# 基座模型可能做的是"续写"：接着编造更多问题，如
#   '北京有什么好玩的景点？\n上海有什么好玩的景点？\n广州有什么好玩的景点？...'
inst = pipeline("text-generation", model="Qwen/Qwen2.5-0.5B-Instruct")
print(inst([{"role": "user", "content": q}], max_new_tokens=100)[0]
      ["generated_text"][-1]["content"])
# 指令模型则会真正列举景点（故宫、长城、颐和园……）——SFT+对齐带来的行为改变
```

**练习 C：规模直觉计算器。** 把 1.4 节的估算公式写成函数，扫码式地比较几个模型。

```python
def train_flops(n_params_b, tokens_t):
    """C ≈ 6ND。参数单位十亿(B)，token 单位万亿(T)。"""
    return 6 * n_params_b * 1e9 * tokens_t * 1e12

def gpu_days(flops, gpus=1024, tflops_per_gpu=400, util=0.45):
    """有效算力 = 峰值 × 利用率；返回 gpu·天 数。"""
    eff = gpus * tflops_per_gpu * 1e12 * util
    return flops / eff / 86400

for name, n, d in [("Llama-2-7B", 7, 2), ("Llama-3-8B", 8, 15), ("Qwen2.5-72B", 72, 18)]:
    c = train_flops(n, d)
    print(f"{name}: C≈{c:.2e} FLOPs, 1024卡约 {gpu_days(c):.0f} 天")
# 预期输出：
# Llama-2-7B: C≈8.40e+22 FLOPs, 1024卡约 5 天
# Llama-3-8B: C≈7.20e+23 FLOPs, 1024卡约 46 天
# Qwen2.5-72B: C≈7.78e+24 FLOPs, 1024卡约 496 天
```
