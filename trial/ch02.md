# 第 2 章 语言模型基础

第 1 章我们把大语言模型定义为"用神经网络实现条件概率 $P(w_t \mid w_{<t})$ 的模型"。但要真正读懂后续章节——从第 3 章的 Transformer 到第 13 章的 RLHF——你还需要一套更扎实的基础设施：语言建模的概率形式化、衡量模型好坏的度量（交叉熵与困惑度）、文本的向量表示（词嵌入），以及从概率分布生成文本的解码策略（temperature、top-k、top-p）。这些概念贯穿全书，且在实践中每一个都对应着 API 里真实的参数。

本章假设你熟悉神经网络与反向传播，因此对"神经语言模型"只做快速回顾，把篇幅留给那些 LLM 时代变得更加重要的内容。学完本章，你应当能：写出语言建模的概率链式分解；解释困惑度的含义并用代码计算它；理解不同解码策略的数学定义与行为差异；并区分语言模型的两种使用方式（概率估计与生成）。

## 2.1 语言建模任务与概率链式法则

### 2.1.1 形式化定义

给定词表 $V$（第 4 章将讨论如何构建词表），一段文本是词序列 $w = (w_1, w_2, \dots, w_T)$，其中每个 $w_t \in V$。语言模型（Language Model）是定义在任意序列上的概率分布 $P(w_1, \dots, w_T)$，满足非负性与归一性。直接为每个序列学一个概率显然不可行——序列空间随 $T$ 指数爆炸。概率链式法则（chain rule of probability）提供了唯一的系统性分解：

$$P(w_1, w_2, \dots, w_T) = P(w_1) \cdot P(w_2 \mid w_1) \cdot P(w_3 \mid w_1, w_2) \cdots P(w_T \mid w_1, \dots, w_{T-1})$$

紧凑地写成：

$$P(w_{1:T}) = \prod_{t=1}^{T} P(w_t \mid w_{1:t-1})$$

其中 $P(w_1 \mid w_{1:0})$ 约定为 $P(w_1)$（无前文条件）。每个因子是一个条件分布，对所有候选词求和为 1：

$$\sum_{w \in V} P(w \mid w_{1:t-1}) = 1$$

这个分解没有任何近似——它是精确的恒等式。语言建模的全部艺术在于：**如何参数化并学习这些条件分布**。n-gram 用查表统计，RNN 用隐状态，Transformer 用注意力，但它们实现的是同一个数学对象。

### 2.1.2 一个数值例子

设小词表 $V = \{\text{猫}, \text{狗}, \text{追}, \text{了}, \text{老鼠}\}$，模型给序列"猫追了老鼠"的打分可能是：

$$P(\text{猫}) = 0.05,\quad P(\text{追}\mid\text{猫}) = 0.10,\quad P(\text{了}\mid\text{猫,追}) = 0.60,\quad P(\text{老鼠}\mid\text{猫,追,了}) = 0.35$$

整句概率为 $0.05 \times 0.10 \times 0.60 \times 0.35 = 1.05\times10^{-3}$。注意两个现象：其一，概率随长度增加迅速衰减到接近零——这正是为什么实践中我们优化对数概率（下文 2.4 节）；其二，"猫追了"之后接"老鼠"（0.35）远高于接"狗"（想象为 0.01），说明条件分布编码了语义搭配。**语言模型的质量，就体现在把概率质量分配给"人类会说的延续"上。**

## 2.2 自回归与自编码：两种建模范式

按链式分解的方向与训练目标，神经语言模型分为两大范式。

**自回归（autoregressive, AR）语言建模**，也称因果语言建模（causal LM）：显式建模左到右的条件分布 $P(w_t \mid w_{<t})$，训练目标是对数似然最大化。代表是 GPT 系列。优点是与生成天然一致——按顺序采样即可；缺点是每个位置只能看到左侧上文（单向上下文）。

**自编码（autoencoding）语言建模**，更准确说是掩码语言建模（Masked Language Modeling, MLM）：随机遮住输入中约 15% 的词，让模型基于**双向上下文**预测被遮的词，即建模 $P(w_{\text{mask}} \mid w_{\text{其余}})$。代表是 BERT。双向上下文让它在理解类任务（分类、抽取、检索）上表现优异，但 MLM 的概率不是真正的序列生成分布——各掩码位置的条件分布互相独立，难以直接用于生成。

$$\text{AR:} \quad \prod_{t} P(w_t \mid w_{<t}) \qquad\qquad \text{MLM:} \quad \prod_{i \in \text{mask}} P(w_i \mid w_{\setminus \text{mask}})$$

| 维度 | 自回归（GPT 系） | 掩码自编码（BERT 系） |
| --- | --- | --- |
| 上下文 | 单向（左侧） | 双向 |
| 训练目标 | 真实序列似然 | 伪似然（遮词重建） |
| 能否自然生成 | 是 | 否（需额外解码技巧） |
| 擅长任务 | 开放式生成、对话 | 分类、匹配、信息抽取 |

大语言模型时代选择了自回归：其一，生成是通用助手的刚需；其二，AR 目标下每个位置都产生一次预测信号、训练效率高；其三，AR 模型可以"顺便"完成理解任务（把问题与选项拼成序列续写答案）。本书后续章节中，除非特别说明，"语言模型"一律指自回归语言模型。

## 2.3 从 n-gram 到神经语言模型：快速回顾

### 2.3.1 n-gram 与平滑

在神经网络之前，条件分布 $P(w_t \mid w_{1:t-1})$ 用最大似然计数估计。完整前文太长，n-gram 模型做马尔可夫假设——只看最近 $n-1$ 个词：

$$P(w_t \mid w_{1:t-1}) \approx P(w_t \mid w_{t-n+1:t-1}) \approx \frac{c(w_{t-n+1:t})}{c(w_{t-n+1:t-1})}$$

其中 $c(\cdot)$ 是词组在语料中的出现次数。例如二元（bigram）模型中 $P(\text{了} \mid \text{追}) = c(\text{追,了}) / c(\text{追})$。

朴素计数有两个致命问题。一是**零概率**：测试集中合法但训练中未见的词组（如"追 过 一 只 花孔雀"）概率为 0，导致整句概率为 0；二是**数据稀疏**：绝大多数 n-gram 组合即使在海量语料中也只出现零次或一两次，估计极不可靠。**平滑**（smoothing）技术把部分概率质量从高频事件匀给未见事件，经典方法有 Laplace 加一平滑、Katz 回插（backoff）与 Kneser-Ney 平滑。其共性思想可概括为折扣再分配：

$$P_{\text{smooth}}(w \mid h) = \frac{c(h, w) - \delta}{c(h)} + \lambda(h)\, P_{\text{backoff}}(w \mid h')$$

其中 $h'$ 是截短的（更短的）历史，$\lambda(h)$ 保证归一化。平滑的细节在 LLM 时代已很少直接使用，但它的核心洞察——**对未见事件保留合理的泛化概率**——正是词嵌入与神经网络带来自动平滑的思想源头，值得了解。

n-gram 的规模困境是指数级的：参数量随 $n$ 以 $|V|^n$ 增长，实践中 $n$ 很少超过 5；而语言的长程依赖（一部长篇小说开头埋下的伏笔在结尾回收）远超 5 个词。要突破，必须让"相似上下文"共享统计强度。

### 2.3.2 神经语言模型：一览

你已经熟悉神经网络，这里只勾勒三代架构解决的核心问题，详细的历史与技术细节留给延伸阅读：

- **NNLM（Bengio et al., 2003）**：查表得到前 $n-1$ 个词的嵌入（embedding），拼接后过 MLP + softmax 输出下一词分布。贡献在于**分布式表示**——"猫"与"狗"向量相近，于是"狗追了"的统计数据自动帮助"猫追了"，突破了 n-gram 的稀疏性。
- **RNN / LSTM 语言模型**：用循环隐状态 $h_t = f(h_{t-1}, x_t)$ 汇总任意长度的历史，理论上突破固定窗口限制；LSTM 的门控缓解了长程梯度消失。但顺序计算无法并行（训练慢），且实践中有效上下文仍有限。
- **Transformer（2017）**：自注意力让每个位置直接"看到"全部上文，训练完全并行，长程依赖一步直达。它是 GPT 系列的骨架，也是本书第 3 章的主角。

从 n-gram 到 Transformer 的主线只有一条：**如何更高效、更长远地表示条件历史 $w_{<t}$**。

## 2.4 训练目标与评测：交叉熵、对数似然与困惑度

### 2.4.1 交叉熵损失

给定训练语料 $D = \{w^{(1)}, \dots, w^{(N)}\}$，语言模型训练最大化对数似然：

$$\mathcal{L}_{\text{MLE}} = \sum_{n=1}^{N} \sum_{t} \log P_\theta\left(w_t^{(n)} \mid w_{<t}^{(n)}\right)$$

等价地最小化**负对数似然**（Negative Log-Likelihood, NLL）。由于模型输出的是词表上的 softmax 分布，这恰好就是模型分布与数据经验分布之间的**交叉熵**（cross-entropy）。对单个位置，若真实下一词为 $y$（词表中索引为 $j$ 的 one-hot 目标），损失为：

$$\mathcal{L}_{\text{CE}} = -\log P_\theta(w_t = y \mid w_{<t}) = -\log \frac{\exp(z_j)}{\sum_{k=1}^{|V|} \exp(z_k)} = -z_j + \log \sum_{k=1}^{|V|} \exp(z_k)$$

其中 $z \in \mathbb{R}^{|V|}$ 是 logits。

> 📌 注：logits 一词在本书中反复出现，含义是"softmax 之前、未归一化的实数得分"。它可以是任意实数（正负皆可），经 softmax 指数化后变成概率。中文社区常译作"对数几率"，其与第 0 章信息论的联系值得注意：$-\log P$ 的单位是 nat（自然对数）；若改用以 2 为底的对数，单位是 bit，此时交叉熵除以序列长度即得到"每 token 的编码比特数"——语言模型本质上是在给文本做最优算术编码，这正是香农信息论视角下的语言建模。详见维基百科 [Cross entropy](https://en.wikipedia.org/wiki/Cross_entropy) 与 [Kolmogorov complexity / 香农信源编码定理](https://en.wikipedia.org/wiki/Shannon%27s_source_coding_theorem)。

交叉熵损失对 logits 的梯度有一个极其简洁的形式（ softmax 输出分布减去 one-hot 目标）：

$$\frac{\partial \mathcal{L}_{\text{CE}}}{\partial z_k} = P_\theta(k \mid w_{<t}) - \mathbb{1}[k = j]$$

这个优美的性质让误差信号"干净"地回传到整个网络，也是第 6 章讨论训练稳定性时反复出现的对象。实践中因为多个 $t$ 求和后数值巨大，通常取平均并配合混合精度训练，详见第 6 章。

在 PyTorch 中：

```python
import torch
import torch.nn.functional as F

logits = torch.randn(2, 5, 100)      # (batch=2, seq_len=5, vocab=100) 的未归一化输出
targets = torch.randint(0, 100, (2, 5))  # 每个位置的真实下一 token

# 交叉熵：默认对非 batch 维度取平均
loss = F.cross_entropy(logits.reshape(-1, 100), targets.reshape(-1))
print(f"交叉熵损失 = {loss.item():.4f} nats/token")
```

### 2.4.2 困惑度

**困惑度**（Perplexity, PPL）是语言模型最常用的评测指标，定义为交叉熵的指数（以自然对数计，单位为 nats 时）：

$$\mathrm{PPL}(w_{1:T}) = \exp\left(-\frac{1}{T}\sum_{t=1}^{T} \log P(w_t \mid w_{<t})\right)$$

它有一个漂亮的等价表述——序列概率的几何平均值的倒数：

$$\mathrm{PPL} = \frac{1}{\sqrt[T]{P(w_1)\cdots P(w_T)}}$$

**直观解释**：PPL 是"模型在每个位置平均把概率质量均匀分给了多少个词"。PPL = 1 意味着模型每次都完美确定（概率 1）地预测对下一词；PPL = $k$ 等价于模型在正确词与另外 $k-1$ 个词之间均匀犹豫。因此 **PPL 越低越好**。一个随机猜的模型 PPL 等于词表大小 $|V|$；好的现代模型在自然文本上可到个位数到十几（视数据集而异）。

一个帮助记忆的比喻：想象模型每一步带着"加权骰子"选择下一词，PPL 就是这颗骰子的等效面数——面数越少，模型越"笃定"且"笃定得对"。

```python
import torch
import torch.nn.functional as F

def perplexity(logits: torch.Tensor, targets: torch.Tensor) -> float:
    """计算困惑度。

    logits:  (batch, seq_len, vocab)
    targets: (batch, seq_len)  每个位置的真实下一 token
    """
    # 逐位置交叉熵（reduction='none'），再对 batch 与序列维取平均
    nll = F.cross_entropy(
        logits.reshape(-1, logits.size(-1)),
        targets.reshape(-1),
        reduction="none",
    )
    return torch.exp(nll.mean()).item()

torch.manual_seed(0)
logits = torch.randn(4, 32, 50000)            # batch=4, 长度 32, 词表 5 万
targets = torch.randint(0, 50000, (4, 32))
print(f"随机初始化模型 PPL ≈ {perplexity(logits, targets):.1f}")  # 应接近 50000
```

随机模型 PPL 应接近 $|V|$（上例约 50000），训练后迅速下降——PPL 曲线是预训练监控的第一指标。使用 PPL 时注意三点：**PPL 只在同一个分词器与同一个数据集下可比**（不同词表的"每 token 熵"不可直接比较）；PPL 低不代表生成质量高（一个背诵训练集的模型 PPL 极低但毫无用处，这也是第 11 章数据污染话题的一个侧面）；因此最终评测仍需任务级指标（第 11 章）。

## 2.5 词嵌入与分布语义

### 2.5.1 分布假设与 one-hot 的困境

神经网络不能直接吃词，词必须变成向量。最朴素的方案是 one-hot：每个词是一个 $|V|$ 维、仅一处为 1 的向量。但 one-hot 有两个问题：维数等于词表大小（现代 LLM 词表 10 万+）；且任意两个不同词的内积为 0——所有词两两"正交"，语义关系完全不可见。

**分布语义假说**（distributional hypothesis）指出："一个词的含义由它出现的上下文决定"（Firth, 1957: "You shall know a word by the company it keeps"）。与"狗"出现在相似上下文中的词（猫、宠物、奔跑）应具有相近的表示。**词嵌入**（word embedding）正是把词映射为低维稠密向量（如 256–16384 维），并让语义相近的词在向量空间中彼此靠近。

### 2.5.2 从 word2vec 到 LLM 的输入层

word2vec（2013）用极简的自监督任务学习嵌入：在滑窗内预测中心词（CBOW）或预测上下文词（skip-gram），训练后得到著名的线性规律，如 $\text{vec}(\text{国王}) - \text{vec}(\text{男}) + \text{vec}(\text{女}) \approx \text{vec}(\text{女王})$。GloVe 则基于全局共现统计。这些静态嵌入有一个根本局限：**一词一义**——"苹果"在"吃苹果"与"苹果发布会"中向量完全相同。

在 LLM 中，嵌入层（embedding layer）是可训练的查表矩阵 $E \in \mathbb{R}^{|V| \times d}$，它只是第一层：输入词的静态向量随后经过几十层 Transformer 的**上下文化**（contextualization）处理，同一个词在不同语境中得到不同的"动态表示"。静态嵌入负责提供词的先验语义，上下文化负责消歧——这个分工在第 3 章看完注意力机制后会豁然开朗。嵌入维度 $d$（即"隐藏维度"或 $d_{\text{model}}$）从 GPT-2 small 的 768 到 Llama 3 70B 的 8192 不等。

```python
import torch

vocab, d = 1000, 64
emb = torch.nn.Embedding(vocab, d)   # 查表矩阵，可训练
ids = torch.tensor([[3, 17, 3]])      # 注意 id=3 出现两次
vecs = emb(ids)                       # (1, 3, 64)
print(vecs.shape)
print(torch.allclose(vecs[0, 0], vecs[0, 2]))  # True：静态嵌入无上下文，两处相同
```

## 2.6 生成与解码策略

训练好的语言模型在每个位置输出词表上的概率分布 $P(\cdot \mid w_{<t})$；**解码**（decoding）就是决定"从分布中实际选哪个词"的策略。不同策略在"质量"与"多样性"之间做不同的取舍，是 LLM 应用中最常被调用的旋钮。

### 2.6.1 贪心解码与随机采样的两难

**贪心**（greedy）每步选概率最大的词：

$$w_t = \arg\max_{w \in V} P(w \mid w_{<t})$$

贪心确定性强、可复现，但容易陷入重复循环（"我觉得这个很好。这个很好。这个很好。……"），且每步只顾局部最优，可能错过全局更自然的序列——概率第二的词后面也许跟着概率极高的延续。

另一个极端是**纯随机采样**：严格按分布 $P(\cdot \mid w_{<t})$ 抽样。它多样性最高，但在长尾分布（LLM 输出往往如此）中会频繁抽到不合理的低概率词，一句话就毁掉整段生成。好的解码策略都在这两极之间找平衡。

### 2.6.2 beam search

**束搜索**（beam search）保留每步概率最高的 $k$ 条（束宽 $k$）候选序列，结束时取整句对数概率最高者。形式上，它近似搜索 $\arg\max_{w_{1:T}} \prod_t P(w_t \mid w_{<t})$。束搜索在机器翻译等"输出短且基本唯一"的任务中有效，但在开放式生成中表现不佳：高概率序列往往是乏味、重复、通用的（Holtzman et al., 2020 的著名观察——人类语言本身并不是每词都取最大概率的）。因此现代对话 LLM 几乎不用束搜索，而转向下面一族**随机截断采样**（stochastic truncation sampling）方法。

### 2.6.3 temperature：调节分布的"温度"

**温度**（temperature）通过在 softmax 里除以 $T$ 来重塑分布：

$$P_T(w_i \mid w_{<t}) = \frac{\exp(z_i / T)}{\sum_{j} \exp(z_j / T)}$$

$T \to 0$ 时分布趋向 one-hot（等价贪心）；$T = 1$ 即原始分布；$T > 1$ 分布被"拉平"，采样更随机、更有创造性（也更冒险）。直觉：温度低，粒子（概率质量）聚集到能量（logit）最低的态；温度高，粒子四处扩散。

> 📌 注：这个比喻并非修辞——softmax 在统计物理中就是 **Boltzmann 分布**（也称 Gibbs 分布），温度 $T$ 正是热力学温度的角色，logit 对应能量的负值。这也解释了"温度"一词的由来。想了解这条物理连线的读者可参见维基百科 [Softmax function § Statistical mechanics](https://en.wikipedia.org/wiki/Softmax_function#Statistical_mechanics)；HuggingFace 文档则给出了工程侧的参数说明（[temperature](https://huggingface.co/docs/transformers/main_classes/text_generation#decoding-strategies)）。

### 2.6.4 top-k 与 top-p（核采样）

温度重塑整个分布，但不截断长尾。**top-k 采样**只在概率最高的 $k$ 个词中重新归一化后采样，硬性砍掉长尾：

$$\text{Top}_k = \{ \text{概率最高的 } k \text{ 个词} \},\qquad P'(w) = \frac{P(w)}{\sum_{w' \in \text{Top}_k} P(w')}\ \ \text{for } w \in \text{Top}_k$$

**top-p 采样**（又称核采样，nucleus sampling；Holtzman et al., 2020）改为动态截断：保留累计概率达到 $p$ 的最小词集合（"核"），在核内重新归一化采样。它的聪明之处在于自适应：当模型很确定（分布尖锐）时核很小，只挑几个候选；当模型犹豫（分布平坦）时核自动扩大，保留更多分支。实践上 top-p（如 $p=0.9$）配合适度温度（$T \in [0.7, 1.0]$）是聊天模型最常用的配置。

### 2.6.5 完整采样实现

下面一段自包含的 PyTorch 代码实现了上述全部策略（贪心、温度、top-k、top-p），并用一个小型分布演示它们的差异。它是理解第 14 章（投机解码也建立在采样之上）与第 13 章（RLHF 中"采样动作"就是采 token）的垫脚石。

```python
import torch
import torch.nn.functional as F

def sample_next_token(
    logits: torch.Tensor,          # (vocab,) 当前位置的 logits
    temperature: float = 1.0,      # 温度，越小越接近贪心
    top_k: int | None = None,      # 只在概率最高的 k 个词中采样
    top_p: float | None = None,    # 核采样：保留累计概率达 top_p 的最小集合
    greedy: bool = False,          # True 则直接取 argmax
) -> int:
    if greedy:
        return int(logits.argmax())                     # 贪心：直接取最大 logit

    # 1) 温度：softmax 前将 logits 除以 T
    z = logits / max(temperature, 1e-5)

    # 2) top-k：把第 k 名之后的 logits 置为 -inf（softmax 后概率为 0）
    if top_k is not None:
        kth = torch.topk(z, top_k).values[-1]           # 第 k 大的 logit
        z = torch.where(z < kth, torch.full_like(z, float("-inf")), z)

    # 3) top-p：按概率从高到低累加，超过 p 的部分截断
    if top_p is not None:
        sorted_z, sorted_idx = torch.sort(z, descending=True)
        cum = torch.cumsum(F.softmax(sorted_z, dim=-1), dim=-1)  # 累计概率
        # 找到第一个使累计概率超过 top_p 的位置，其后的全部屏蔽；
        # 同时保留刚越过阈值的那一项（保证集合是最小的且累计 >= p）
        mask = cum - F.softmax(sorted_z, dim=-1) > top_p
        sorted_z[mask] = float("-inf")
        z = sorted_z[torch.argsort(sorted_idx)]         # 恢复原始词表顺序

    # 4) 从最终分布中采样
    probs = F.softmax(z, dim=-1)
    return int(torch.multinomial(probs, num_samples=1))


if __name__ == "__main__":
    torch.manual_seed(42)
    # 模拟上下文"北京的天气真"的下一词 logits（仅示意）
    vocab = ["好", "冷", "热", "的", "不错", "糟糕", "下雨", "离谱"]
    logits = torch.tensor([3.0, 2.2, 2.0, 1.5, 1.2, 0.5, 0.1, -1.0])

    print("贪心：", vocab[sample_next_token(logits, greedy=True)])
    for T in (0.5, 1.0, 1.5):
        sampled = [vocab[sample_next_token(logits, temperature=T)]
                   for _ in range(2000)]
        p_good = sampled.count("好") / 2000
        print(f"T={T}: '好' 被采样频率 {p_good:.2f}")
    print("top-k(k=2) 样例：",
          [vocab[sample_next_token(logits, top_k=2)] for _ in range(5)])
    print("top-p(p=0.9) 样例：",
          [vocab[sample_next_token(logits, top_p=0.9)] for _ in range(5)])
```

### 2.6.6 解码策略选择速查

实践中如何选？给出一组经验速查，供动手时参考：

| 场景 | 推荐配置 | 理由 |
| --- | --- | --- |
| 代码补全、事实问答、数学 | 贪心或 $T \le 0.3$ | 答案基本唯一，追求确定与准确 |
| 通用对话助手 | $T \approx 0.7$，top-p $= 0.9$ | 平衡流畅与多样，业界默认档 |
| 创意写作、头脑风暴 | $T \approx 1.0$，top-p $= 0.95$ | 鼓励长尾分支 |
| 抽取式任务（输出短且格式固定） | 贪心 或束搜索（$k=3\sim5$） | 输出空间小，搜索有效 |

两个补充注意点。第一，temperature 与 top-p 同时调节时效果会叠加（先缩放再截断），调参时应固定一个、扫另一个；第二，解码策略只在**推理期**起作用，不改变模型权重——这与第 10 章的微调、第 13 章的对齐有本质区别：前者是"如何使用分布"，后者是"改变分布本身"。当提示工程与解码策略都无法消除的坏行为（如总是先说"作为一个 AI……"），就需要靠后训练解决了。

## 2.7 语言模型的两种使用方式

同一个语言模型 $P(\cdot \mid \cdot)$，在实践中被当作两种不同的机器使用。

**方式一：概率估计器（打分）**。输入完整序列，输出其对数似然或某个位置的条件概率。用途包括：文本分类（比较各候选标签续写的概率，argmax 选标签）；重排序（如检索结果的 rerank）；困惑度作为文本质量/语言fluency 度量；以及第 13 章中 PPO/GRPO 的关键技术——对模型自己生成的序列**逐 token 计算对数概率**以估计策略梯度。这种方式一次前向传播即可，无需循环。

**方式二：生成器（采样）**。如 2.6 节所示，反复采样拼接，自回归地产生新文本。对话、写作、代码补全都属于此类。生成成本高得多——$T$ 个 token 需要 $T$ 次前向（第 14 章的 KV Cache 正是为削减其重复计算而生）。

理解这一区分对后续章节至关重要：**评测与 RLHF 大量使用方式一，应用与部署围绕方式二展开**，而两者的底层是同一个条件分布。下面用 HuggingFace 展示方式一的最小示例（与本章自实现代码互补）：

```python
from transformers import AutoTokenizer, AutoModelForCausalLM
import torch

model_name = "Qwen/Qwen2.5-0.5B"   # 小模型，CPU 也能跑
tok = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name)

texts = ["今天天气真好，适合出门散步。", "今天天气真好，适合出门微分。"]
for t in texts:
    ids = tok(t, return_tensors="pt").input_ids
    with torch.no_grad():
        out = model(ids).logits[0, :-1]        # 每个位置预测下一词
    nll = torch.nn.functional.cross_entropy(
        out, ids[0, 1:], reduction="none")      # 与真实下一词对齐
    ppl = torch.exp(nll.mean()).item()
    print(f"PPL = {ppl:7.3f} | {t}")
# 通顺句子的 PPL 显著低于搭配不当的句子——语言模型天然可以当文本打分器
```

## 本章小结

- 语言建模 = 链式法则分解 + 条件分布学习：$P(w_{1:T}) = \prod_t P(w_t \mid w_{<t})$。自回归（GPT）单向建模可生成；掩码自编码（BERT）双向建模擅理解。LLM 选择了自回归。
- n-gram 用计数 + 马尔可夫近似，受稀疏性限制；平滑给未见事件留概率的思想由神经网络的分布式表示（词嵌入）自动化地实现。
- 训练目标是最小化交叉熵（负对数似然），其对 logits 的梯度形式极简：softmax 概率减 one-hot。困惑度 $\mathrm{PPL} = \exp(\text{平均交叉熵})$，即"等效均匀候选词数"，越低越好，但只在同一分词器与数据集内可比。
- 词嵌入基于分布假说把词映射为稠密向量，LLM 中静态嵌入 + Transformer 上下文化共同完成语义表示。
- 解码策略光谱：贪心（确定、易重复）↔ 温度采样（多样、冒险）；beam search 适合短输出，开放式生成用 top-k / top-p 截断长尾，top-p（核采样）能自适应调整候选集大小。
- 语言模型有两种用法：概率估计器（打分、分类、RLHF 中的对数概率）与生成器（自回归采样循环）；前者一次前向，后者 $T$ 次前向。

## 练习

1. **推导题**：证明 softmax 交叉熵损失对 logits 的梯度 $\partial \mathcal{L}/\partial z_k = P(k) - \mathbb{1}[k=y]$（从 $\mathcal{L} = -z_y + \log\sum_k \exp z_k$ 出发，分 $k = y$ 与 $k \neq y$ 两种情况求偏导）。
2. **概念题**：某模型在词表大小 50000 的数据集上 PPL 为 50，另一个模型（分词器不同、词表 32000）PPL 为 30。能说后者更好吗？给出至少两条理由，并思考"按字符归一化的每字符熵"如何缓解这一问题。
3. **编程题**：把 2.6.5 节的 `sample_next_token` 扩展为完整的 `generate(prompt_ids, max_new_tokens, **kwargs)` 循环函数，接在 2.7 节加载的 Qwen2.5-0.5B 上，分别在 $(T{=}1.0)$、$(T{=}0.5, \text{top\_p}{=}0.9)$、贪心三种设置下生成同一段开头，对比输出的流畅性与重复性。
4. **实验题**：固定一个 prompt，绘制"采样频率 vs 温度"曲线：令 $T \in \{0.1, 0.3, 0.5, 0.7, 1.0, 1.5, 2.0\}$，统计每个 $T$ 下最高频 token 的出现比例，观察分布如何从聚集走向均匀。
5. **思考题**：为什么人类写作的文本在贪心解码下往往不是"每词最优"？这一事实对"用对数似然衡量生成质量"意味着什么？（可参考延伸阅读中 Holtzman et al., 2020 的分析。）

### 实操：编程练习

**练习 A：从手写 softmax 交叉熵到 PPL，并用小模型给句子打分。** 本练习串起 2.4 节的两条公式：$\mathcal{L}_{\text{CE}} = -z_y + \log\sum_k e^{z_k}$ 与 $\mathrm{PPL} = \exp(\overline{\text{NLL}})$。

```python
import torch
import torch.nn.functional as F

torch.manual_seed(0)

def ce_and_ppl(logits, targets):
    """手写 softmax 交叉熵与 PPL，并与 F.cross_entropy 对账。
    logits: (T, V)，targets: (T,)"""
    z_y = logits[torch.arange(len(targets)), targets]        # 取出真实词的 logit
    nll = -z_y + torch.logsumexp(logits, dim=-1)             # 逐位置 NLL（手写公式）
    assert torch.allclose(nll, F.cross_entropy(logits, targets, reduction="none"), atol=1e-5)
    return nll.mean().item(), torch.exp(nll.mean()).item()   # 平均 CE 与 PPL

logits = torch.randn(10, 50)
targets = torch.randint(0, 50, (10,))
print("CE = %.4f nats, PPL = %.3f" % ce_and_ppl(logits, targets))
# 随机 logits 下 PPL 应在词表大小 50 上下（随机模型基线 ≈ |V|，因目标均匀抽取）

# 真模型打分：通顺句 PPL 应明显低于乱搭配句
from transformers import AutoTokenizer, AutoModelForCausalLM
tok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B")
model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B")
for t in ["今天天气真好，适合出门散步。", "今天天气真好，适合出门微分。"]:
    ids = tok(t, return_tensors="pt").input_ids
    with torch.no_grad():
        lg = model(ids).logits[0, :-1]                      # 预测下一 token
    nll = F.cross_entropy(lg, ids[0, 1:], reduction="none")
    print(f"PPL = {torch.exp(nll.mean()):8.2f} | {t}")
```

**练习 B：batch 采样与解码策略统计。** 实现"一次对整个 batch 的 logits 并行采样"，并统计不同温度下同一分布的采样频率（对应 2.6.5 节）。

```python
import torch
import torch.nn.functional as F

def batch_sample(logits, temperature=1.0, top_k=None, top_p=None, n_samples=10000):
    """logits: (B, V) -> 采样结果计数。演示 temperature/top-k/top-p 的组合。"""
    z = logits.repeat(n_samples, 1, 1).reshape(-1, logits.size(-1))
    z = z / max(temperature, 1e-5)
    if top_k is not None:                       # top-k：截掉第 k 名之后
        kth = torch.topk(z, top_k, dim=-1).values[:, -1:]
        z = torch.where(z < kth, torch.full_like(z, float("-inf")), z)
    if top_p is not None:                       # top-p：截掉累计概率超出 p 的尾部
        sz, si = torch.sort(z, descending=True, dim=-1)
        p = F.softmax(sz, dim=-1)
        mask = (p.cumsum(-1) - p) > top_p
        sz[mask] = float("-inf")
        z = torch.gather(sz, -1, torch.argsort(si, dim=-1))
    return torch.multinomial(F.softmax(z, -1), 1).squeeze(-1)

torch.manual_seed(0)
logits = torch.tensor([[3.0, 2.2, 2.0, 1.5, 1.2, 0.5, 0.1, -1.0]])  # "的"占优的分布
p1 = F.softmax(logits[0], -1)
print("理论概率(T=1):", [f"{x:.3f}" for x in p1.tolist()])
for T, tk, tp in [(1.0, None, None), (0.5, None, None), (1.0, 2, None), (1.0, None, 0.9)]:
    idx = batch_sample(logits, temperature=T, top_k=tk, top_p=tp)
    freq = torch.bincount(idx, minlength=8) / len(idx)
    print(f"T={T}, top_k={tk}, top_p={tp}: 首词采样频率 {freq[0]:.3f}")
# 预期现象：T=0.5 时首词频率高于 T=1；top_k=2 时只有前两个词被采到；
# top_p=0.9 截掉了长尾（频率应集中在累计 90% 的头部几个词上）。
```

**练习 C：对数概率与序列打分（方式一的雏形）。** 计算整句对数似然，并体会"概率连乘 → 对数相加"的数值稳定性（呼应 2.1.2 节"概率迅速衰减到零"）。

```python
import torch, torch.nn.functional as F

torch.manual_seed(1)
T, V = 50, 50000
probs_seq = torch.softmax(torch.randn(T, V), dim=-1)        # 模拟模型输出的条件分布
targets = torch.randint(0, V, (T,))                         # 模拟真实文本

p_prod = 1.0
for t in range(T):
    p_prod *= probs_seq[t, targets[t]].item()
print(f"连乘概率 = {p_prod:.3e}")                           # 典型量级 1e-220，极易下溢
loglik = torch.log(probs_seq[torch.arange(T), targets]).sum().item()
print(f"对数似然   = {loglik:.3f} nats")                    # 稳定的等价值
print(f"PPL        = {torch.exp(-loglik / T):.1f}")         # 随机模型 + 随机目标：约 5 万~8 万
```
